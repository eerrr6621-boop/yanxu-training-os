# 研序 · 培训运营中心（Yanxu Training OS）

覆盖培训公司完整业务链的全流程运营平台：需求 → 投标立项 → 项目 → 师资排课 → 交付 → 评估 → 回款 → 课酬 → 成本 → 归档。

刻意保持**无框架、无构建**：单个 Java 17 进程（JDK 内置 HttpServer + 嵌入式 H2）服务一个原生 JavaScript 单页应用。部署即一个静态目录 + 一个进程。

> English docs: [README.md](README.md)

当前版本：**1.10.0**（2026-09-28），源码于 2026-09-29 同步。[访问研序](https://training.jxyftd.tech/) ·
[更新记录](https://training.jxyftd.tech/updates.html) · [新版说明与配置边界](docs/RELEASE_V1_10.md)。

本版在原电脑端界面中接入组织岗位权限、邮箱首绑与核验、需求审批、课程认证、交付课酬、问卷结果导入和总结 Word 导出。仓库提供源码与合成测试，不包含实际人员、账号密码、生产数据库、邮件凭据或私有材料。

## 亮点

- **运营工作台（今日运营）**：按逾期、开课临近、排课缺口、材料就绪与回款节点自动排列行动队列，支持严重度筛选（全部/紧急/关注/常规）、按天分组的开课时间线、项目健康进度条与经营快照。
- **V13 简约科技视觉**：沿用科技展示定位，更新 ImageGen 透明品牌标记、原生系统字体、浅色导航与搜索/账户工具栏。项目页采用连续排版和克制的结算侧栏，统一表单、表格、弹窗及手机触控规范。
- **公开培训资料中心**：首页左上角提供免登录入口，外部访客可下载已上架学习包；系统管理员和业务管理员可一次选择或拖入最多 20 份文件，逐份修改标题、查看进度与重试失败项，并完成上下架、删除和下载统计。
- **师资简历与智能推荐**：在师资资源中私有上传 PDF/PPTX 简历、核对专业画像，并从已有需求或客户原话识别主题、行业与对象后给出可解释候选。系统实绩与简历自述分开展示，推荐不会自动排课。
- **项目工作区**：风险优先视图，阻塞与提醒按业务记录合并并直达待处理行；完成交付与归档由真实闭环校验把关。
- **岗位权限与审批**：基础角色结合机构、区域和岗位授权控制范围；直接承接按负责人、BP顺序审批后由团队承接，外部投标在系统内登记结果。
- **结果导入与总结**：导入原问卷平台结果，支持预览校验、重复检查、修正版独立复核；内部人员编写总结，负责人和BP复核后导出Word。旧问卷接口保留兼容。
- **交付与课酬**：区分预计、计划、实际和计酬课时，支持授课及开发酬金、制度逐笔核准、已付/未付及跨日更正、旧制迁移和编码结算表。金额每笔四舍五入到分后汇总。
- **响应式与可访问性**：桌面 / 平板 / 手机三套布局，键盘导航、焦点管理、尊重 `prefers-reduced-motion`。
- **现代认证与接口边界**：HttpOnly Cookie 会话、PBKDF2 密码散列及旧哈希兼容迁移；写接口严格限制方法、JSON 类型、有限数值与业务状态机。
- **回归套件**：API、权限、业务和模块专项使用合成数据与临时隔离库；另有前端、地区调度/迁移、语义辅助和离线天气专项。

## 快速开始

环境：Java 17+（完整回归套件还需要 Node 18+、Python 3）。可选本地语义辅助另需独立 Python 环境，见 [启用说明](semantic/README.md)。

```bash
./run.sh --demo     # Mac / Linux；Windows 用 run.bat
```

打开 <http://localhost:8080>。演示模式在全新隔离的 `demo-data/` 库中注入示例数据与体验账号：

| 角色 | 账号 | 密码 |
|---|---|---|
| 系统管理员 | `admin` | `admin123` |
| 业务管理员 | `manager` | `manager123` |
| 只读用户 | `viewer` | `viewer123` |

不带 `--demo` 启动使用 `data/` 目录，不创建示例老师、培训或项目。空库会创建一个 `admin` 账号：可通过私有 `bootstrap.admin.password` 配置至少12位密码，或使用首次启动时仅在本机显示的随机密码。不会删除已有数据。实际生产使用还需独立配置人员来源、权限和邮箱核验，参见新版说明。

## 持续维护

每次发布都必须重新编译 Java 17 后端，并在三套相互隔离、仅绑定 loopback 的临时数据库上执行全部回归。运行 `bash scripts/check.sh` 会先检查前端资源、脚本、图标与版本，执行 102 项财务/需求填写/业务图标/阶段状态断言，并完整解码核验 14 枚透明图标，再完成编译与三套 API 测试，结束后会停止临时服务。正式数据和正式凭据不会进入质量门禁。涉及安全边界的改动还应同步更新 `docs/SECURITY.md` 与 `CHANGELOG.md`。

没有 Java 时，可单独运行 `node scripts/check_frontend.cjs`、`node scripts/test_frontend.cjs` 和 `node scripts/check_business_art.cjs`，默认不联网。给第一条命令增加 `--base-url http://127.0.0.1:8080` 可只读核验页面资源的状态、类型及哈希。
