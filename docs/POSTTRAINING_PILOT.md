# 离线后训练小试：已训练，未上线

日期：2026-09-07。实验编号：`pilot-bf41f9b29232a5b9`。

## 结论

本次确实更新了原始模型权重，再导出 FP32 / INT8；不是仅增加提示词、规则或重跑测试。相同架构和量化方式下，INT8 文件仍为 57,239,135 字节，本机独立推理进程峰值约 201 MiB，与训练前基本相同。训练进程峰值约 941 MiB，训练在本机离线进行，没有给线上服务器增加训练负载。

**暂不替换生产模型。** 新合成封存题的原段落检索改善，但现有预处理存在误删证据和保守拒绝，训练资料还存在明显的长度/风格偏差。结果不是业务准确率，也没有证明真实简历匹配或全国交通覆盖已经达标。

机器可读摘要：[匿名实验结果](../semantic/reports/posttraining-pilot-20260907.json)。前置基线：[二十轮评测](TWENTY_ROUND_EVALUATION.md)。

## 数据、训练及隔离

- 80 条训练查询（10 个主题），16 条开发查询（另 2 个主题）；每题 1 段正例、3 段难负例。
- 另由独立上下文编写并审阅 32 条封存查询（4 个新主题）。训练前固定题目文件摘要，完成最终检查点后才在评估脚本中读取。未根据开发/封存结果选择轮数、检查点或阈值。
- 全部为 AI 构造的合成证据及标签，**未经业务人员双人标注验收**；数据模块中的“人工标注”不能理解为真实业务专家已确认。负例表示文字不足以支持要求，不表示某位老师实际没有能力。
- 未把既有 19 份个人简历、旧灰度资料或二十轮题目用于本次训练；本次也没有对 19 份简历进行训练后回归。合成分组隔离不替代新讲师、新文件模板的真实业务盲测。
- 基础版本：`BAAI/bge-small-zh-v1.5@7999e1d3359715c523056ef9478215996d62a620`。仅微调现有编码器，参数数 23,953,920，新增参数 0。
- 固定 CPU 单线程、seed 20260907、2 epoch、学习率 1e-5、AdamW、temperature 0.05、梯度累积 4、裁剪 1.0，共 40 次优化器更新。使用组内对比损失，无跨样本负例。
- 训练文本最大实际长度 65 token，配置上限 256，超长时拒绝而非静默截断。测试不能证明长简历训练或推理的资源上限。
- 复用已有本机构建环境，使用独立进程和私有输出目录；未新装依赖、下载权重、调用外部模型或上传数据。原模型权重和生产 Java / worker 源码按冻结摘要核对未改。
- 保留原模型与实验模型，实验 manifest 使用新的模型名和版本，记录基础版本、数据摘要及权重摘要，`production_approved=false`。生产版本白名单不放宽；只有独立评估脚本加载实验模型。独立复核直接调用未改动的生产 `Encoder`，实验 FP32 和 INT8 均在 manifest 检查阶段被 `Unexpected model manifest` 拒绝，未进入推理或磁盘缓存初始化。未启动实验 HTTP 服务。

方法背景可参考 [BGE 对比微调说明](https://bge-model.com/tutorial/7_Finetuning/7.1.2.html)；本次 CPU 脚本不是照搬其 CUDA 示例。

四组开发题各有 4 次 worker 防护拒绝、封存题各有 2 次，均计入分母，不删除困难题。原版至后训练 INT8 的封存原段落首选为 14 题改善、0 题退化；worker 为 6 题改善、2 题退化，净增 4 题。

## 已知风险与具体未解决问题

1. **长度捷径明确存在于训练资料。** 80/80 训练题和 16/16 开发题的正例都是唯一最长段落。只选最长段落就能通过全部开发题；开发结果不能证明真正理解了主体、授课角色和课程内容。
2. 独立封存题的“选最长段落”基线为 18/32。在这项策略选错的 14 题上，原版 INT8 答对 3 题，后训练答对 10 题，所以不能断言模型只是选最长；但长度和叙述风格捷径尚未排除。后续需重新构造长度平衡、正例有长有短的训练资料及全新封存集，不能反复调本次封存集后声称盲测。
3. `holdout_env_06` 的“尚未实施的排期都不计入”含“尚未”，`holdout_crop_02` 的排除条件含“不是”，当前 guard 将整个需求转人工核对。这是输入边界规则，不是模型推理故障；不能为提高测试分数直接删除所有否定保护。
4. `holdout_env_07` 的正例明确表示本人完成两个单元授课，但授课确认依据中含“签到”，当前整行过滤把有效证据一并删掉。应识别“本人授课”与“仅负责签到”的角色关系，而不是只按词出现就剔除。
5. **排除条件被当成检索目标。** `holdout_care_03` 的正向要求上，后训练正例 0.713 高于负例 0.661；但“只承担一个单元或只编教材都不满足”被拆为另一条匹配目标，正例 0.416 反低于教材负例 0.523，取各段最小值后选错。文化服务题也复现同类问题。应区分正向要求和排除条件，不能仅把所有句子都当作需要相似的内容。
6. 分句过滤还可能删掉“没有承担本次讲授”，却保留前句“课程已结课”，丢失否定与主体关系。分钟数、个人/团队场次、授课/岗位年份仍可能混淆；需要结构化硬条件核对，不能让相似度替代事实判断。
7. 既有 Java 词表准入漏荐、多条件覆盖及角色判断问题仍保留。更多训练轮数不能补回未传入模型的原文，也不能修正模型之后的错误排除。

## 服务器影响

同架构、同 INT8 导出方式下，本次文件大小完全相同，独立推理峰值相差约 0.42 MiB，只能解释为“基本不变”，不能宣称内存优化。训练需要额外保存梯度和优化器状态，应继续放在开发机离线完成，不在业务服务器上边服务边训练。

封存题冷向量缓存 worker 中位耗时：原版 INT8 21.109 ms，后训练 21.379 ms。每轮开始清空内存向量缓存，再做独立热缓存重复，并校验结果相同；热缓存约 0.12 ms 不是一般模型推理耗时。RSS 是包含启动、哈希、缓存和 Python 的整个评估进程峰值，不是常驻服务稳态或 Linux 生产压测结果。

回滚保留两套文件会增加磁盘占用；只有同时加载两套模型才会叠加相应内存。尚未在目标服务器验证长文本、并发和资源限制，不据此承诺生产上限。当前未部署，线上没有本次实验导致的新增负担。

## 交通仍是独立未完成项

本次训练不学习或生成车次、航班、运行时间、同城位置。此前 9,861 项交通逻辑检查通过，不等于逐条核实全部城市实际时刻。

371 个城市是产品目录；当前文件实际只有 72 条来源记录、69 个列车样本、39 个涉及城市、68 个有向城市对（34 个无向对，含未决路线），不是全国完整时刻库。“32 组”是首批双向参考子集，不是每个城市均已覆盖。没有提供真实全量铁路排除库或航班数据库。

找到一班符合阈值的双向依据可支持该城市进入参考范围，但一班慢车不能证明所有列车都超过 4 小时。没有查全不能伪装为“无高铁”，也不能据此错误转航空。完整时刻源尚未取得；逐条公开核对仍可推进，但未完成部分必须保持待核实。缺完整批量数据源不是停止核实其他合法公开线路的理由。覆盖和来源限制见[交通覆盖记录](TRANSPORT_COVERAGE_V7.md)。

## 复现实验

从仓库根目录运行；需要已有本地模型和匹配版本的构建环境。以下命令只生成新的私有临时输出，不安装依赖、不替换模型、不启动服务。`PILOT_PY` 请指向已有构建环境的 Python，`PILOT_DIR` 会产生一个新目录；不要改成公开目录或代码仓库内部。

```bash
PILOT_PY=/path/to/existing-build-venv/bin/python
PILOT_DIR=$(mktemp -d /private/tmp/yanxu-posttrain-repro.XXXXXX)
"$PILOT_PY" semantic/test_posttrain_pilot.py
"$PILOT_PY" semantic/train_posttrain_pilot.py --base-dir semantic/model --output-dir "$PILOT_DIR/training"
"$PILOT_PY" semantic/export_posttrain_pilot.py --base-dir semantic/model --training-dir "$PILOT_DIR/training" --output-dir "$PILOT_DIR/export"
"$PILOT_PY" semantic/evaluate_posttrain_pilot.py --training-dir "$PILOT_DIR/training" --model-dir semantic/model --precision fp32 --output "$PILOT_DIR/base-fp32.json"
"$PILOT_PY" semantic/evaluate_posttrain_pilot.py --training-dir "$PILOT_DIR/training" --model-dir semantic/model --precision int8 --output "$PILOT_DIR/base-int8.json"
"$PILOT_PY" semantic/evaluate_posttrain_pilot.py --training-dir "$PILOT_DIR/training" --model-dir "$PILOT_DIR/export" --precision fp32 --output "$PILOT_DIR/trained-fp32.json"
"$PILOT_PY" semantic/evaluate_posttrain_pilot.py --training-dir "$PILOT_DIR/training" --model-dir "$PILOT_DIR/export" --precision int8 --output "$PILOT_DIR/trained-int8.json"
```

依赖实测：PyTorch 2.8.0、Transformers 4.57.3、ONNX Runtime 1.23.2、NumPy 2.2.6、tokenizers 0.22.1，Darwin arm64。本次复现入口和合成题可保留在代码库；权重、缓存和原始报告不进入 Git 或公共资料目录。运行时间和 RSS 会随机器变化。

下一步验收应先修证据结构和预处理，再以长度平衡资料独立训练，并用获授权、业务复核的全新真实简历检查完整推荐流程。当前实验保留用于比较，不直接上线。
