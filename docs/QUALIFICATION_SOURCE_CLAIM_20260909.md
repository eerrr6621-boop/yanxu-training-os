# 资格依据与课程名称分离（2026-09-09）

本次已完成本地修复、19份历史简历回放及完整回归，尚未上线。解决的是资格材料的错误引用，不是模型后训练收益，也没有把简历自述变成已认证资格。

## 实际问题

原 `RequirementConstraints` 取第一条含“认证／资格／证书”的安全记录作为资格待核项的引用。实际历史V08中因此出现：要求讲师授课资格，却引用其讲过的服务资格认证培训课程；另有会计、人力、理财或音乐证书被挂到该项。

原状态一直是 `needs_evidence`、`verified=false`，没有因此自动准入。但引用范围不准确，容易让用户误以为已经找到对应讲师资格材料，或看不到后面真正相关的声明。

## 本地改动

- 新增 `QualificationClaim`，只从明确的取得／持有／具备等声明或认证讲师身份描述中寻找展示材料。课程名、介绍如何取证、参训结业、计划、他人/机构持证、同记录中的失效或免责声明不作为本人资格依据。
- 具名资格必须在同一声明中关联所请求主题；普通教师／讲师资格单独标作通用资格，不把它说成某门课的专项授权。
- 原教学事件过滤保持不变。资格展示使用同一已限定源范围内、进入教学事件过滤前的安全记录；它们只进入资格待核项，不进入授课记录或评分。混合章节和被遮蔽章节的边界没有放宽。
- 保留连续原文、证据ID、原行、规范匹配文本中的UTF-16偏移，注明 `unverified_resume_statement`。所有资格检查仍必须人工核验。
- 查询标记为 `bounded_not_exhaustive`：未展示引用不等于简历没有任何资格，也不等于该讲师没有资格；这个有界提取器不承担完整资格认证或任意语法理解。
