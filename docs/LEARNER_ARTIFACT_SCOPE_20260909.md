# 课堂材料对比与讲师经历否认的分离

2026-09-09。本地研发记录，未发布，不是模型准确率或完整推荐验收报告。

## 原始问题及修复

原PD30资料中的“整期结束后，学员带走的是空白纪要模板，不是客户信息”，描述的是学员获得的材料。原Python worker仅因“不是”清空整段证据；Java叙述层还把材料中的“模板”当成虚构履历限制。

新增Python learner_artifact.py及Java LearnerArtifactContext，识别完整的“学员领取/带走教学材料—对比信息资料”或“结课后留下教学材料—对比信息资料”句子。须在同段前面已有明确本人完成授课表述。对象必须是有界名词，不接受本人、同事、授课记录、履历、资格证明、否定动作、未知谓语、额外更正或模板转述上下文。不是按课程主题或题号列例外。

整句保留于原上下文，但不参与正向检索或能力证明。叙述层只增加learner_artifact_context_only关系，不新增或更改授课人、学员对象、课程、完成状态、形式等事实。后续否认本人经历、同事授课、助教和未来计划仍由原检查处理。完整事件评分入口也不再把已排除的材料对比重新放入向量。

需求侧代码、量化模型、分数阈值、真实讲师字段和历史标签均未改变。worker中只有_nonproof_spans函数改动，另98个顶层节点不变。

## 实际模型和业务结果

使用同一原BGE INT8，两套实际编译的业务代码及旧/新worker独立进程，分别运行原30条需求加6条新对照，每边328份候选输入。共72次真实模型比较、无worker错误。旧版前30条逐项复现上轮模型输出（仅计时不同）、候选审计和名单。

- 原PD30的两份本人授课资料由无证据恢复为完整检索单元，相似度分别0.739420、0.685491。这是相关性，不是准确率或资格认证；第二份的对象故意不符，恢复其真实原文不代表符合需求。同事授课反例仍不计分。
- 原PD30与PD42的证据/上下文处理变化，其他28条需求完整候选审计和模型输出不变。原30条的准入和最终名单均不变。
- 19份真实简历×8条历史需求的152份候选审计逐字段不变。这是已暴露历史回归，不能据此称真实简历准确率提高。
- 新3个通用主题分别检查现场/远程要求，共6条已知缺陷对照。每条包含正确形式、形式不符、对象不符、同事授课、计划授课、助教、后续否认、不同课程、仅材料描述9种候选。修改前均无人选，修改后各只选中预期的本人/正确对象/正确形式者；6条恢复、没有新增错误准入。它们是开发控制，不是新盲测。
- Node逐项复算3011处原文范围，需求结构和既有事件字段前后一致；检索引文没有重新包含材料对比句。所有输入、模型、源码及编译类摘要核对。

**原PD30、PD42、PD08完整需求仍未成功推荐，不将恢复检索或新控制题通过包装成完整业务达标。** PD30还存在“通话纪要整理—通话纪要的写法”的同义内容/经历绑定；“我是该班的主讲人”、课堂方法说明及“我负责从示例讲解到练习后的答疑”等叙述仍未完整承载。Java的广泛“示例”限制也仍需按归属处理。比较内容仍被需求层拆成多个主题。

## 回归与保留的失败

- Java90项检查通过；Python5项测试方法覆盖324条肯定、63条资格/否定/歧义对照及3条待处理跨行格式。加外层空白变体，780条输入的Java/Python原文范围协议实际核对通过，包括补充平面Unicode字符。
- 首次测试文件补丁因check.sh实际classpath与预期不一致原子失败，确认未部分写入后修正。
- 首次跨语言测试及完整回归实际失败：把“材料名词后换行再写不是客户信息”错误地归作应无任何引文的负例。单独编译原版检查，发现旧、新Java均保留相同的前一物理行，但整段allowed=false、无可用授课事件；Python亦保持不完整。这是已有跨行处理问题，不是本次恢复。
- 原跨行文本没有删除，转为明确的未解决格式样本，继续断言原文范围、完整事件不可用及旧/新检查结果完全相同。没有改业务代码来掩盖这个失败，首次日志保留为full-regression-initial.log。它仍是后续待修缺陷。
- 最终完整隔离回归退出0，师资产品87通过、0失败；测试仅使用临时回环服务和一次性数据库。测试枚举数不是业务准确率分母。
