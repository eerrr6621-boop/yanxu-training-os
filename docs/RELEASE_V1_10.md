# 1.10.0 源码发布说明

系统版本于 2026-09-28 上线，本仓库于 2026-09-29 同步公开源码。保留原有 Java 17 后端、原生 JavaScript 前端和电脑端界面。

## 本版功能

| 模块 | 已接入能力 |
|---|---|
| 人员与权限 | 统一账号、机构岗位、区域和机构数据范围、可信人员来源导入、邮箱首绑和登录核验 |
| 需求与承接 | 需求字段、45分钟课时、直接承接审批、团队受理、外部投标结果登记 |
| 审批 | 负责人和BP顺序办理、退回重提、撤回、兼任处理、办理记录和站内提醒 |
| 课程与师资 | 课程目录、讲师与课程认证维护、按资格推荐和缺口提示 |
| 交付与课酬 | 授课核对、授课和开发酬金、逐笔制度核准、已付/未付及跨日更正、旧制迁移、编码结算表 |
| 统计 | 课时和金额明细、机构/课程汇总、范围控制及导出 |
| 问卷结果 | 原平台结果导入、预览、逐题有效值统计、查重、修正版独立复核和替换 |
| 培训总结 | 内部填报、业务数据引用、负责人及BP复核、照片和Word导出 |

课程分类不等于讲师资格；正式资格和人员岗位需由使用方提供并维护。外部投标审批继续由原办公流程负责。金额采用逐笔人民币两位 HALF_UP 后汇总，制度适用由核准人员逐笔确认。

## 启动与配置

1. 安装 Java 17，在仓库根目录运行 `./run.sh`；Windows 使用 `run.bat`。
2. 空库启动不创建老师、培训或项目。首次管理员密码可通过私有 `bootstrap.admin.password` 指定（至少12位），否则由首次启动生成并仅显示在本机。
3. `--demo` 显式使用独立 `demo-data/` 与合成账号。不要将演示库作为正式业务库。
4. 实际部署需独立配置人员来源、岗位授权、邮件通道和登录策略。源码默认启动方式用于本地开发，不会携带已部署站点的账号和配置。
5. 启用 `login.email.mode=required` 前，应完成可信身份与邮箱准备，配置邮件发送并验证送达。缺少配置不会自动降级绕过核验。

详细技术接口参见 `docs/modules/`。其中部分文档保留开发阶段的历史背景，不能用历史“未完成”或“待确认”文字推断当前站点状态，也不能直接把旧候选配置用于新部署。

不包含真实人员名单、个人邮箱、账号密码表、验证码、SSH/SMTP凭据、生产数据库、上传附件、私有来源原件、内部任务历史或构建缓存。人员接收和真实运维记录未纳入。更新记录页面只保留项目开源链接，不发布个人联系方式。

恢复已有生产系统时，数据库、附件与私有配置应通过使用方自己的备份流程处理。本次源码同步不执行网站部署、不替换线上数据库，也不改变线上账号。

## 验证入口

准备 Java 17、Node 20 和 Python 3.11，并在测试用 Python 环境安装 `requirements-test.txt` 中的依赖后，运行 `bash scripts/check.sh`。主要回归使用合成数据与独立临时目录；openpyxl仅用于独立读取并核验XLSX导出，不是生产依赖。可选浏览器检查和历史语义实验需另外提供相应运行时；涉及私有简历或历史研究材料的实验不会随源码提供输入。

可选的 `*Browser.mjs` 检查通过标准 `playwright` 包加载浏览器驱动，运行者需在自己的 Node 环境中安装该包和所需浏览器。主要CI不依赖维护者电脑上的缓存或私有文件路径。

常用无服务检查：`node scripts/check_frontend.cjs`、`node scripts/test_release_days.cjs`。真实发信、真实员工试用与外部材料校验不应由公开CI自动执行。
