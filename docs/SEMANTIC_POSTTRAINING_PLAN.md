## 结论

可试验，但应做小型检索模型的**监督对比微调**，不是聊天模型式的对话训练。当前为 BAAI/bge-small-zh-v1.5，512 维、最长 512 token，正式推理读取本地 ONNX INT8。官方支持需求 `query`、相关证据 `pos`、易混淆证据 `neg` 格式。[模型卡](https://huggingface.co/BAAI/bge-small-zh-v1.5) · [数据格式](https://bge-model.com/tutorial/7_Finetuning/7.1.1.html) · [官方训练说明](https://bge-model.com/tutorial/7_Finetuning/7.1.2.html)

不能直接继续训练现有量化 ONNX 文件，应从原始可训练权重创建独立实验版本，再导出并量化。INT8 是部署优化，训练后须重新检查其准确性影响。[ONNX Runtime 量化说明](https://onnxruntime.ai/docs/performance/model-optimizations/quantization.html)

## 先把错误分开，再决定训练内容

| 错误来源 | 处理位置 | 后训练是否直接解决 |
| --- | --- | --- |
| 原文没有提取出来、标题与正文断开 | 简历解析、章节与角色结构化 | 不能，模型没有看到证据 |
| 模型找到相关老师，但被词表或逐项准入误排除 | 召回与证据判定规则 | 不能只改模型权重 |
| 同主题的参训、助教、工作岗位被当成个人授课记录 | 主体—课程—角色—时间证据关系 | 结构化优先，微调可辅助排序 |
| 同义需求或相邻专业排错 | 需求—证据相关性模型 | 适合对比微调 |
| 高铁/航班时刻缺失、过期或来源不完整 | 交通数据与核对规则 | 不能交给语言或向量模型编造 |

训练目标是更好地区分“相关且有证据”和“文字相似但证据不成立”。城市、交通、预算、排期、讲师等级不加入专业能力的训练标签；不能让模型学成“名气大或级别高就更相关”。缺少文字不代表老师不会讲，应单列证据不足，不能把未知一律当作能力负例。

## 数据准备与防止测试泄漏

1. 本轮测试和既有 19 份简历只能证明已获测试授权，不能据此默认获准把个人简历用于训练或外发。获得明确训练授权后，仅抽取脱敏的课程与角色关系，避免训练姓名、联系方式、住所、价格。
2. 本次二十轮及此前反复使用的题目冻结为回归资料，不用于学习参数、挑阈值或挑最佳训练轮数后再宣称独立提升。
3. 新建训练资料与开发集，再保留来自**新讲师、新需求、新文件模板**的最终测试集。按讲师、源文件、课程模板及近重复段落分组拆分，不能把同一份简历随机拆句放进训练和测试两边。
4. 可先规划数百条经业务复核的需求—正例—难负例作为小规模可行性试验；这是试验预算建议，不是“达到某个条数即可保证准确”。每项由两位业务人员复核，对分歧仲裁；不把当前模型得分或“最终选中了谁”直接当标准答案。
5. 标签至少区分：明确满足、仅部分满足、只有相关工作/参训/助教、无对应证据、确切否定。未知不当作“已证实不具备能力”。每条保留授权范围、证据行、标签理由、版本、分组 ID 和标注状态。

## 训练与部署边界

- 使用独立环境、输出新检查点，不覆盖当前工作模型。当前运行环境并无已验证的训练脚本。
- 官方示例使用 CUDA/FP16/DeepSpeed；不能直接在现有 Mac 推理环境运行同一安装命令。单设备 CPU/MPS 的兼容性、峰值内存、步耗时需另行小试；57 MB 部署文件不等于训练只需 57 MB 内存。[官方训练示例](https://github.com/FlagOpen/FlagEmbedding/blob/master/examples/finetune/embedder/encoder_only/base.sh) · [官方依赖](https://github.com/FlagOpen/FlagEmbedding/blob/master/setup.py)
- 当前 Transformers 固定为 4.57.3，应保留独立依赖锁；不能照抄新版参数后升级现有生产环境。训练费用和时长未实测，不承诺免费算力或固定用时。
- 下载依赖后尽量本地离线训练，关闭外部实验跟踪和 Hub 上传。原始文本、向量、检查点均作为私有派生数据保护；删除原简历不等于删除模型已学习的信息。
- 目前 `worker.py` 校验固定原版 model/revision，`prepare_model.py` 也只导出固定原版。上线微调版前必须增加派生版本 manifest，记录基础版本、训练数据摘要、tokenizer、查询前缀、分段规则、导出器和量化器；不能冒用原版 revision。
- 新版权重、tokenizer、预处理变化后缓存独立失效；不能混用旧向量。模型的 MIT 许可不替代个人数据训练授权。

## 验收门槛

对同一冻结最终集比较：原版 FP32、原版 INT8、微调 FP32、微调 INT8。记录正式返回精确率、正确人选在准入阶段的召回率、首选命中、无合适人选时拒荐、授课角色误判，以及第三名整数分并列造成的额外入选。不可只看训练损失降低或分数变高。

交通、预算、排期、未知数据和权限等关键规则不得违规；微调版的独立测试排序/召回应改善，且指定课程、实际授课、否定、多模块各组不能明显退化。若仅开发集变好或与基线持平，就保留现有模型。最后才做目标服务器的内存、延迟和并发测试，人工确认后灰度替换。
