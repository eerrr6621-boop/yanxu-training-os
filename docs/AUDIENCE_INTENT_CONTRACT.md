# 培训对象的需求意图边界

本次改动服务于投标前按主题选择候选：客户填写“本次培训对象”，不等于要求讲师以前已给完全同对象讲过同课。原实现没有把普通未来对象设置为 `teachingHistory=true`；问题在于未来对象无条件进入 `features` 硬证据检查。

## 三类要求

| 意图 | 数据/证据处理 | 缺少证据 |
|---|---|---|
| 纯未来对象字段或明确未来叙述对象 | 原文、规范输入、检索输入不变；独立 `audience_context` 保留对象、课程引用和来源范围 | 不单独阻断主题初选，提示“对象适配待确认” |
| 明确必须适配/适合/面向/针对对象 | 完整闭合谓词产生硬对象条件，仍需同课程源对象说明；不要求凭空增加完成历史 | 硬待核；同主题或高相关分不能补足 |
| 明确本人过去教过该课程与该对象 | 原课程历史条件继续核验本人、完成状态、独立要求及课程—对象引用；有界单课程显式对象历史另保留硬对象条件 | 缺项、他人/助教、未完成、跨课程对象不得替代 |

普通课程历史要求与未来对象字段并列，不自动增加“同对象历史”的绑定；明确回指“给这类学员讲完这门课”则仍是硬绑定。受众排除、排他条件、资格、数量比较、括号不完整及不能可靠承载的明确硬表达不降级；保留全文并待核。资格真实性仍须另行核验。

## 审计不能反向成为门槛

`audience_context` 是独立数组，不进入 `requirement_coverage`，没有硬检查 `status` 字段，明确 `hard_requirement=false`。它在同一次评估已有源记录上附加：

- `requested_audience`、`course_ids`、精确 code-point 来源范围及用于计算该范围的 matching text；完整操作日期/预算字段可能已等长空格化，不能把该范围称为原始字段范围。
- 同课程源对象类型说明是否存在、源记录是否自述了已完成同对象经历。此信息不是外部核验，也不等于已擅长或已适配该对象。
- 固定提示“对象适配待确认”。未见同对象记录只表示资料未明确，不能推断讲师无法适配。

该数组不参加 `checks.every`、失败计数或 `hardSupported`。未来对象的提示进入可见 gaps，但不会改变 `_admitted` 的计算。明确的硬对象条件仍在硬检查数组中，和上下文审计分开。

## 边界及验收

AudienceIntent 只处理需求语法，不引入岗位或行业同义词表。仅解析已拥有课程/历史语法之外的残余谓词，避免把课程标题里的“必须”等字样当成资格。完整“面向X、已完成N次工作坊的讲师”协调结构只提取对象X；原数量、形式与个人完成要求仍由原联合事件检查承载，未知后缀不得被截掉。

新 `AudienceIntentTest` 固定于实现前：310项纯Java断言覆盖未来对象非硬化、完整源范围、明确适配/历史、未知后缀、主语开头硬条件、资质/排除及数据容器隔离。四组原诊断输入和所有旧失败在私有审计目录保留；旧测试中要求未来对象必须硬拒的断言需显式契约迁移，不删除测试。

补充的命名课程主语边界：残句以完整 `《课程名》` 开头且强模态在书名号外时，仅在当前需求恰有一门课、名字逐字相同、外部适配谓词完整闭合的条件下正解析。多课程、错课名、括号未闭合、未知资格或其它未知硬谓词都保留待核，不转成全局对象、不吞掉后缀。完整标题内的“必须适配”等字样仍是课程名数据，不能生成硬指令。此项只改需求残句判定，不改变证据或模型。

新 `AudienceNamedSubjectTest` 在该边界修复前固定：19项覆盖支持/缺失/不同对象、普通主语对照、标题内模态、多个课程、错课名、未知后缀及未闭合语法。原12次纯Java诊断中的2次误放行结果不改写，另存同字输入的修复后回放及源码、类文件、运行依赖前后摘要。

没有改动 worker、模型、交通、阈值或旧封存输出，没有运行模型。该补丁不证明最终推荐收益；真实候选及完整 pipeline 应在新源码冻结后另做固定回放。
