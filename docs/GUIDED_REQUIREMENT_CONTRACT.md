# 引导需求字段契约：第一阶段，本地未发布

本次只修复引导输入的字段丢失及来源标记，不表示自由文本理解、事件归属或此前模型验收已经通过。没有训练新模型，没有改动旧评测标签，没有写入正式数据库。

## 已确认的缺口

前端原本有独立的培训主题、参训对象、目标等控件，却仅把整理后的 `requirement` 文本交给后端。对象标签是“参训对象”，而现有硬条件解析使用“培训对象”等另一套标签。两个不同领域的隔离 HTTP 对偶均复现：引导模式错误接受不同受众的候选，同样内容换成标准对象字段则正确。

原基准共21项断言，4项通过、17项失败；其中两个真正匹配受众的正例和标准纯文本路径本来就通过。修复后同21项全部通过。后续扩展后实际 HTTP 回归为47项通过，不将扩展测试误称为同一组21项对比。

## 请求契约

引导模式保留现有 `requirement` 原文，同时提交：

```json
{
  "requirement_contract": {
    "schema_version": "guided_requirement_v1",
    "fields": {
      "unit": "",
      "topic": "培训主题原值",
      "audience": "参训对象原值",
      "goals": "",
      "date": "",
      "hours": "",
      "preference": "",
      "extra": ""
    }
  }
}
```

八个字段都必须存在且是字符串，空值保留为空字符串。禁止额外字段或额外契约属性，不接受未知版本。当前界面没有独立 `industry` 字段，本版本不预留虚构入口；未来扩展应修改版本和前后端契约。

| 字段 | 原前端标签 | 标准匹配标签 | 长度上限 / 第一阶段用途 |
| --- | --- | --- | --- |
| unit | 客户单位 | 客户单位 | 200；客户背景 |
| topic | 培训主题 | 培训主题 | 200；内容条件，必填 |
| audience | 参训对象 | 培训对象 | 200；完整授课对象条件 |
| goals | 希望解决的问题 | 培训目标 | 1600；本次培训目标，不是历史经历 |
| date | 期望日期 | 授课日期 | 80；有效 YYYY-MM-DD 日期或空 |
| hours | 预计课时 | 预计课时 | 32；有限正数字符串或空 |
| preference | 师资要求 | 师资要求 | 1200；补充要求，未完整结构化则待核 |
| extra | 补充说明 | 补充说明 | 1200；补充要求，未完整结构化则待核 |

长度按现有 Java/JavaScript 字符串的 UTF-16 单元计算。上述控件是单行输入，字段内换行或控制字符会被拒绝，不能用插入新标签的方式改变字段归属。

后端按现有前端 renderer 的字段顺序、标签和 ECMAScript trim 重新验证原文。原文与字段不一致、原文多出要求，或 `requirement` 与 `requirement_text` 冲突，均返回400，而非选择一份并丢弃另一份。字段原值保留，不因 NFKC 规范化被覆盖。

## 已有需求和来源

从已有需求带入后，以用户本次编辑的八字段为准；保留 `demand_id` 来源，但不把旧 content/title/teacher_req 再拼成第二套硬条件，不写回原需求。

日期、课时同样取当前字段。用户明确清空时保持未知，不恢复旧需求的日期或课时，也不从历史课程日期推断本次安排。省市和交通仍由原独立调度字段处理，本次未修改交通规则。

`analysis.requirement_input` 保留：

- 原始 `original_text`、字段 `raw_value` 和整理后的 `matching_text`。
- 全部八字段的 `field_ledger`，包括未填写字段。
- 每个非空字段的 `original_span` 与 `canonical_span`，使用 Unicode code-point offsets。
- 字段路径、用途、规范化说明、来源 demand ID，以及待核字段清单。

规范化后的 Coverage 引用标记为 `requirement_canonical`，不能继续叫 `requirement_original`。引用与 `requirement_contract.fields.<字段>` 的映射另存；字段原文和规范化文本的 offsets 不互相冒充。部分旧式检查本身没有细粒度 span，本阶段不编造逐字来源，仍可通过完整字段账本核对。

## 待核边界

- 主题和完整参训对象交给现有 Coverage/Constraints 检查；不得用不同课程的对象补证。
- 普通业务目标保留为培训目标，不据此制造老师本人已完成教学的经历。
- 非空 preference/extra 尚未形成完整结构，第一阶段一律保留待核，不宣称现有字符串解析已理解完毕。
- 主题、目标或单位字段中出现明确约束，或讲师完成教学、让学员执行课堂动作等结构信号，也保留为字段待核；不在本轮猜测动作对象、完成事实或绑定关系。
- 待核字段会在前端显示，并在候选的逐项检查中保留字段来源，核对前不自动准入。单纯填写主题、正确对象和普通培训目标的正例仍能通过，不采取“全部拒绝”策略。
- 原纯文本入口保持兼容，已有未知条件保护不删除；**本次不保证任意开放式原话都能完整理解**，此前自由文本误准入与漏荐不能因为八字段修复就标为解决。

## 后续架构方向，未在本轮实现

继续按失败句增加多套正则不能解决结构性问题。建议后续分阶段引入共享的两类对象，而非另训V5掩盖输入和归属错误：

1. **需求条件**：条件ID、类型、值/比较算子、硬性或偏好、适用于本次交付还是既往授课、事件/事件组范围、字段和原文span、解析状态。
2. **授课事件**：事件ID、课程、本人/他人/机构主体、主讲/协作/助教/学员角色、完成/计划/未知状态、对象、形式、次数/时长、学员活动；每个事实保留独立证据span、完整上下文和肯定/否定状态。
3. 每个明确子条件要么进入结构，要么携原文待核；不能只返回已识别主题并让其余文字消失。条件检查必须绑定同一个应匹配的事件或事件组，不能借另一欢迎会的对象、另一课的数字，或把讲师完成授课当学员完成作品。
4. 模型只对服务器构造和验证过的检索单元排序，不证明事实、不产生资质；后续再收敛 Java/Python 重复的事件判断，保留授权、隐私、来源核验、版本、容量和超时边界。
5. 先写跨域对偶验证主体、完成状态、同课对象、课堂产出、逐场与累计、唯一与多义回指、跨课程数字、附带材料工作不抹杀真正主讲。旧标签保留，按字段遗漏、事件归属、条件支持及最终准入分别评估；不依赖全部改成待核获得安全数字。

本次仅实现上述方向的输入字段保真第一步，全文事件结构尚未实现。
