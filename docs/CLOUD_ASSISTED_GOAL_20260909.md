## 新目标

建设可在研序中使用的云端辅助师资推荐：保留已有简历、常驻城市入口、本地交通参考与规则；先复用有效资料，缺失或有歧义时调用经过验证和授权的云端模型进行证据分析或交通资料补查。程序负责约束、校验和排序，网页呈现真实进度、推荐依据及未确认项。优先验证 Gemini 3.8 Flash 的可用接入，后端适配器不绑定单一供应商。暂停新增预训练、后训练及逐句规则补丁扩张，不再以穷举全国所有城市组合为本次上线前置条件。

全国城市的输入识别和后续可扩展能力保留。按“实际授课城市 × 有真实常驻地的讲师城市”处理当前请求，同时把未覆盖城市保留为可查询队列；不能把按需覆盖宣传为全国已经查齐。

## 处理链路

网页提交需求 → 研序后端任务 → 本地有效资料/交通参考 → 必要时云端分析或检索 → 证据校验与固定排序 → 推荐名单与说明。

### 简历和需求

1. 原文件、解析文本、页码/段落 ID 及版本留在研序。云端仅接收获授权的最少必要文本；本地替换姓名为候选 ID，去除电话、邮箱、身份证、家庭地址和不必要客户标识。脱敏不等于匿名，也不自动产生外发授权。
2. 首次分析或原文改变时，模型提取主题、对象、本人角色、已经完成/计划、独立/辅助、授课方式及原文引用；需求也结构化。不重复分析未变化的简历。
3. 本地硬条件仅处理真实常驻地、预算、档期和明确冲突等确定事实。旧词表/小模型“没找到证据”不提前永久剔除候选，应标未知进入云端复核，避免在新模型看到原文前已经漏荐。小模型可保留为低成本检索助手，而非复杂证据的最终裁判。
4. 云端对满足就近范围的候选按统一量表给出需求匹配分项和原文依据。不只给旧排序前三名让云端重排；必要时分批覆盖当前就近池，验证批次评分一致性。
5. 每项证据校验候选 ID、原文引用、上下文、本人/他人和否定关系。程序验证 JSON 并不等于已验证事实；引用真实存在也不等于其逻辑支持结论。材料只支持“简历有此自述”，不自动变成系统实际授课记录。未知、冲突必须允许返回。
6. 缓存按文本版本、需求、模型版本、提示版本、量表版本、规则版本和人工更正失效；跨用户/组织隔离。云端结果不直接覆盖人工履历字段，不把推荐模型分数当作成功概率。

### 交通

1. 先读服务器上有效的有来源参考。同城依据已确认常驻城市，不能从任职单位或履历出现的城市推测。
2. 不足时，检索真实公开/获授权来源，再由模型提取“出发城市—到达城市—交通方式—参考时间—来源与日期”。外部搜索只发送城市/路线条件，不发送简历或客户需求。普通模型记忆不作交通时间来源。
3. 程序继续执行双向铁路各小于 240 分钟优先；只有存在适当的铁路不满足依据，才将双向直飞各小于 180 分钟列入航空后备。铁路未查到不等于没有合格铁路。不能用直线距离、反向镜像或不同班次任意拼接补数。
4. AI 可以检查现有数据的方向、单位、重复、过期和来源冲突，也可以提出待复核修改；不能直接改写或为自己生成的数据自证。新来源应有可核对的实际内容与归属。原独立复核门槛不因模型声明“已验证”而跳过；如以后调整审核机制，须显式评审，不能悄悄下调。
5. 采用可长期存储、按政策过期复核的城市交通参考。不是给用户卖票或选具体班次，也不要求用户填写查询日/乘车日；这些日期保留在后台证据审计中。长期复用不代表永久有效。
6. 来源缺失、冲突、检索失败时返回待核实。允许显示已有合格结果和未完成城市，但不声称已全量比较后得出绝对最优。

### 排序和人数

- 保留“就近优先 → 同一就近优先级内比较需求匹配 → 同分时讲师等级择高”的顺序；原有就近分层/时长规则单独测试，不让模型自行设权重。若需改动分层定义，先记录为明确业务变更。
- 等级顺序：讲师、高级讲师、特级讲师、特聘讲师。等级不覆盖交通门槛或硬性需求。
- 目标至少三位；同一就近池按匹配与等级选人，边界同分按现有业务规则扩展。只有在本层合格人选不足时才逐层补充后备，不凭综合加权把远处名气大的老师挤到前面。
- 实际合格不足三位就明确人数不足、缺哪类资料；不捏造人选、不降低事实门槛。不自动派课，保持投标立项前的推荐定位。

## 有边界的实施与验收

1. **接入确认**：专用于研序的服务端配置、用途和数据授权明确后，先用无个人信息的合成文本做最小连接/结构化/检索/引用能力测试。不给第三方发送真实简历以探测可用性。不读取或搬用其他应用存放的访问令牌。
2. **本地实现**：可替换供应商适配器、规则与证据校验、缓存、限额、任务状态接口和页面真实阶段。无云端配置时原功能继续工作，并准确标注没有执行云端分析。
3. **固定评测**：先冻结已有关键难例和旧回归，再对授权的 19 份真实简历做相同需求下的新旧对照。已经看过的历史题不叫盲测；未有人核对的 AI 标签不叫真实准确率。新增独立业务验收集在确定候选方案后一次使用，不把失败题反复改写直到数字好看。
4. **停止条件**：首次端到端评测后最多两次有明确原因的提示/流程修正，再给出采用或不采用结论，不自动回到无限训练或无限换模型。硬条件、本人/他人、否定与计划混淆是关键失败；已知关键错荐未解决则不替换。相关性、漏荐、证据支持、延迟和实际费用分别报告。
5. **灰度与上线**：先小范围可回退验证；满足固定业务标准和运行限制后，才发布服务器并同步 GitHub。缺失来源可按需继续补充，不为上线宣称全国已覆盖。上线仍需有效发布连接和真实浏览器验收。

调用上限、重试上限、并发和预算在配置中设有限值；遇到配额/权限错误不轮换身份或绕过限制。模型服务失效可返回已核实的本地结果及清楚的局限，不能把旧结果伪装成本次新分析。
