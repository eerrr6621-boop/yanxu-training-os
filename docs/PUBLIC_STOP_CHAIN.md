# 公开单列停站链：城市参考制备

本地制备可以复用政府、铁路公开页面中同一列车的明确停站时钟，不需要实时车票接口，也不要求前台展示班次。

`PublicStopChain` 只解析以下通用结构的完整原文：

```text
去程G812次：福州08:00始发→泉州08:45/08:50→厦门09:40终到。
返程G813次：厦门10:00始发→泉州10:45/10:49→福州11:40终到。

G812/3次

福州站7:53始发，11:38终到厦门北站
```

以上是合成测试例，不是实际列车资料。头部需有明确 `G`、`D` 或 `C` 服务编号；此字符识别表示铁路服务标识，并不单独证明高速铁路属性。初站必须写始发，终站必须写终到，中间站必须包含完整到达／出发时钟。每个停站及所选端点保留原文 UTF-16 范围。仅允许同一天严格递增的单列停站链；未知跨日、不带到发角色的单一中间时钟、拼接另一车次、重复站名、反向选择、选中间站到达时刻作为出发均拒绝。

也支持独立车次标题下一行的完整“起站＋时钟＋始发，时钟＋终到＋终站”句子。标题与正文必须有真实换行；复合编号如 `G812/3` 原样绑定，不展开或猜测返向编号。端点和时钟只能取各自连续原文 span，不能把跨行碎片合成词。句后附加否定、临时、未来或另一个服务的内容不能丢弃，必须整体拒绝。

同一列车的任意前后站段都可整理，不必逐城市重写一套新闻整句语法。所选起点取发车时刻，终点取到达时刻；返向必须由另外的返向证据独立给出，不镜像去程。站点仍受既有城市归属核查约束，字面标签与规范站名可以在后台另记，不得修改原始片段凑一致。

## 两个接入点

- `PublicStationContext` 的 `SCHEDULE_CHAIN` 使用共享解析器，但保持既有正常图生效日、来源使用范围、审核期、完整性链和严格 `<240` 判断。旧的“新增动车—填补／补强”句式继续由原路径解析。新增支持明确“自某日零时起，全国铁路将实行新一季度列车运行图”的已生效公告：公告日在生效日前并不自动代表今天仍未运行，须先核实明确生效日已过去；此身份只叫正常图参考，不声称授课日服务已确认。
- `CityPlanningReference` 的 `computed_same_service` 也使用同一个解析器。两次核读的端点、服务、到发原文 span 必须精确匹配被选的同一停站链；核读存入的分钟仍须重新按源时钟计算。原来的“站（时开）至站（时到）服务编号”单段格式保持原检验。双读、来源政策、日期、撤销与版本校验不变。

除全国调图公告外，可以使用“自某月某日起，将新增明确站对/编号组，共若干对动车组列车”的确定公告。须全句匹配、产品项数量吻合、所选站对出现在公告中，且实际生效日不晚于研究日/今天。公告仅给出已生效走廊背景，具体服务编号及各向时长仍各自取完整独立时钟句；不利用“对”推算返向旅时，不将压缩的编号组自动扩展成单服务，也不声称今后每天开行。

严格城市参考不等于全城最快或门到门承诺。独立 planning 层仍只提供粗时间档，保留 30 分钟规划缓冲假设；不产生精确评分、铁路排除证明或航空后备触发。存在真实可观察的旅时，不代表可以跳过来源限制；明确禁用或撤销的来源仍不能通过换文件、换标签导入。

## 验证

`scripts/PublicStopChainTest.java` 包含 48 项合成检查，覆盖起终点和中间站、独立返向、时钟颠倒、分钟篡改、错行／错服务、跨日未说明、单钟点角色缺失、未来／临时／停运公告、原文 hash 与 stored bounds 重算。旧交通参考、规划库 102 项和请求级索引 59 项测试保持通过。

`scripts/PublicHeadedEndpointTest.java` 另有 60 项定向检查，覆盖独立标题、复合编号、225/201 不对称的合成时钟、起终角色、跨行拼词、尾部条件、确定生效公告及数量/走廊绑定，以及共用规划解析的原文 span 和存入分钟校验。该测试不表示任何真实城市对已获制备或规划准入。

实际来源、独立读者结果、来源差异、制备 spec 及新合并库仅保存在私有验收目录，不将个人数据或完整商业时刻表提交仓库。只有显式本地配置才会启用；该组件本身没有联网、部署或自动派课能力。
