# 请求级城市参考快照

## 使用方式

```java
CityPlanningReference.Index index = CityPlanningReference.index(today);
for (/* 本次需求的讲师候选 */) {
    Map<String, Object> planning = index.lookup(
        teacherProvince, teacherCity, teachingProvince, teachingCity);
}
```

`index(LocalDate)` 使用独立 planning 文件配置，另有 `index(Path, LocalDate)` 供隔离工具/测试指定私有文件。默认未配置时是无资料快照，不访问文件。

一次 index 对应一次业务请求，**不得存入静态变量、用户会话或跨请求缓存**。`asOf()` 为构建时业务日期，`directionCount()` 为已索引有向城市对数量；`buildMetrics()` 是不可变的本次构建调用计数。

## 验证与只读边界

构建步骤：库文件和完整性锚各读取一次 → 全部来源原文档哈希/核读/方向/时间结构/历史版本一次完整验证 → 预建双向结果 → 递归冻结结果 → 丢弃所有构建期解析缓存。

只有同一次构建内部复用已验证的原文档、方向事实和历史头。它们的解析值在私有 `ThreadLocal` 作用域内，且只在内部执行，无调用方回调。`finally` 总会移除作用域；成功后 Index 只持有冻结的结果与计数，不保留原始 A/B 文档、可变库或解析缓存。原 baseline API 不启用这些 memo。

下一次 index 构建始终重新检查当前文件和锚。不存在“文件坏了就沿用上次 active”的兜底。已有独立锚的历史回退检查继续保留；源文件损坏/删除、锚不匹配、已撤销、源/复核到期都不能靠旧快照自动恢复。

一个已经开始的请求拥有一致的构建时快照，因此中途磁盘改变不会混合新旧结果。更改会在**下一次请求**生效，不声称正在处理的旧请求能在每个 lookup 时立即发现撤销；那将重新引入文件检查。调用方必须遵守按请求构建约定。

返回值是递归不可变 Map/List，包括上下行城市、端点、准备状态、来源背景和分歧列表。未知城市/未观察城市对也返回只读待核结果。快照不产生严格准入、精确分数、航空后备；业务语义与 baseline 完全一致。

## 真实 6 对的隔离测试

`scripts/CityPlanningIndexTest.java` 只读取上一轮已制备的 6 对 / 12 方向私有库，测试变化全部发生于新临时副本。覆盖：

- 12 个方向的全部输出字段与 baseline 相等，原有 102 项 baseline 测试原封不动重放通过。
- 库+锚各读取一次、14 原始文档各解析一次、全库验证一次、12 方向事实各验证一次。
- 重复 100 次 lookup 不触发任何被计数的文件内容读取、原文解析、JSON 文件解析或完整验证。
- 顶层及嵌套结果不可变；一次失败的调用方写操作不能改变下一位老师看到的快照。
- 下一请求能够看到来源/复核过期、文件/锚删除、内容损坏、版本/锚变动、合法新版本撤销和回滚。
- 未撤销城市对不因其它城市对撤销而被修改；原始私有文件及锚不变。

本地 macOS arm64、Java 17.0.16 单进程测量示例（含构建）：

| 查询次数 | 每位老师重新 load+lookup | 一次 load 后 baseline 多次 lookup | 请求级 index |
| --- | --- | --- | --- |
| 24 | 310.35 ms | 130.98 ms | 4.20 ms |
| 100 | 1125.39 ms | 500.94 ms | 3.46 ms |

100 次查询对应的源文档解析调用数分别为 13,200、7,062、14。Index 后续查询阶段计数均为 0；它没有用跳过完整性换取速度，而是将全部验证前置并在单次请求内复用。

这些是一次隔离工具运行的真实调用计数和耗时，**不是生产资源、容量承诺或 SLA**。计数包括实际代码点上的文件内容读取/JSON 解析/验证调用，不包括 `stat`、所有系统 I/O 或哈希序列化开销；本轮没有测生产服务器内存。数据规模扩大后仍需独立压测一次构建的成本。

运行参数：

```text
com.training.CityPlanningIndexTest <已制备私有六对文件> <不存在的新测试输出目录>
```

输出 `index-validation.json` 记录全部测试结果和两组计数/耗时。Index 性能子任务没有改 TeacherIntelligence、NearbySelection、TravelMatrix 或前端。主任务另行接入独立 `planning_reference` / `planning_included` 标识后，使用临时数据进行端到端验收，不把初筛参考改成严格交通保证。
