# 密码通过后的邮箱验证码核心

日期：2026-09-23。本轮在原账号和登录流程中增加服务器验证码挑战，不新建账号体系，不启用待用账号，不修改角色或组织授权。核心实现为 `NotificationChannelsLoginVerification.java`；个人邮箱快照读取复用 `NotificationChannelsAccountEmailPreparation.java`。原 Auth、Api、LoginVerificationHost 及登录卡片由总控接入。

## 服务端接口与职责

`NotificationChannelsAccountEmailPreparation.loginSnapshot(long userId)` 是包内只读方法，返回包内 `Snapshot(userId, revision, email, importBinding)`。只接受导入关系仍有效、当前 status=1 且密码非 NULL/非空的账号；重读候选邮箱及完整连续历史，并核对冻结导入摘要、当前 head 和大小写不敏感的重复邮箱。没有候选、重复、状态或关联变化、历史损坏均固定 409；存储故障固定 503。Snapshot 不返回浏览器，toString 脱敏。

此新增读取分支不放宽原 `/api/account-email-preparation`：管理员仍只能维护导入范围内 status=0、viewer、password NULL 的待用账号。登录核验不创建或更新邮箱准备表，不自动把候选登记成已验证，更不自行激活账号。

核心构造接受 `LongSupplier` 或 `Clock` 和 `MailSender`。`MailSender.send(String email, String code)` 由受信任的宿主组合，不能由 HTTP 参数或客户端选择。

| 接口 | 行为 |
| --- | --- |
| `preflight(remoteAddress)` | 密码校验前登记直接连接来源的请求次数。 |
| `begin(Auth.Credential, remoteAddress)` | 重新核对密码凭证和邮箱快照，预留发送额度，发码后再次核对，返回挑战。 |
| `resend(challengeId, remoteAddress)` | 核对旧挑战后换新 ID 和不同验证码，继承该挑战已有的错误次数。 |
| 包内 `verify(challengeId, code)` | 校验当前凭证及邮箱，正确则原子消费并返回包内 Verified；不签发会话。 |
| `cancel(challengeId)` | 合法 ID 可重复取消；不释放已使用发送额度。 |
| 包内实例 `installTransport(sender)` | 仅受信任宿主/测试使用，作废所有挑战但保留限频计数。 |

`Verified` 仅含 `credential()` 和 `snapshot()`，toString 脱敏。宿主必须在同一 `Api.MUTATION_LOCK` 内完成 `verify → Auth.issueVerified`；Auth 再次校验两份快照，成功后才发原登录会话。Credential 包含撤销代次，显式撤销会话后即使账号字段恢复，旧凭证也不能重新使用。

## 发送、并发和凭证变化

begin/resend 要从业务锁外调用，若调用线程已持有业务锁则 503；宿主也不能把它包进数据库事务。实际步骤为：

1. 锁内核对当前身份、候选邮箱及配额，保存 pending 挑战和验证码 HMAC，预占本次发送额度。
2. 释放业务锁后调用发件器；明文验证码只保留在该次调用的局部对象，调用结束清除引用。
3. 重新持锁核对挑战对象、发件器代次、账号凭证和精确邮箱快照；仍有效才标记 ready 并响应。

发送期间允许正常业务继续。账号停用、改密、改名/角色、显式撤销、邮箱/导入关联改变、出现重复邮箱、取消或更换发件器，都会使旧发送结果失效。旧发送的迟到成功或失败不能删除、覆盖新挑战。邮件发送失败仍占额度，旧挑战不恢复；客户端只收到无 cause 的固定错误。

## 验证码、时限与容量

- 挑战 ID 为 32 随机字节的 64 位小写十六进制；验证码为安全随机六位 ASCII 数字。核心仅保存实例密钥生成的 HMAC-SHA256，并恒定时间比较。
- 从预留时开始 10 分钟有效；重发间隔及同账号重新发起间隔均为 60 秒。每个账号最多一个 pending/ready 挑战，新发起替换旧挑战。
- 错误验证码（含格式错误）累计最多 5 次；前 4 次返回 400，第 5 次移除挑战并返回 401。同一有效挑战的重发或替换不会重置累计错误次数。
- 每账号每小时最多 5 次发送尝试；直接连接 IP 每小时最多 30 次；全局每小时最多 1024 次。成功和失败发送都占用额度。未配置发件器时不调用发送。
- preflight 对直接连接 IP 限制每 10 分钟最多 30 次密码尝试；不得使用未经信任的客户端转发头作为来源。
- 活跃挑战最多 1024；全部 preflight/账号/发送来源计数条目合计最多 4096。容量满时 429，不提前逐出仍有效的计数或挑战。
- 只在各自窗口到期时清理计数，时钟倒退不能绕过限频。取消、验证成功和更换发件器不清理尚未到期的发送额度。

状态仅在单进程内存中保存，实例重建/服务重启会失去挑战和限频计数；旧挑战不能跨实例核验。这不是多节点共享限频或持久设备信任实现。

## HTTP 接线契约

宿主模式 `login.email.mode` 默认 `legacy`；`required` 下所有登录先校验原用户名密码，再邮箱核验，没有管理员旁路。未知模式拒绝登录。required 模式没有发件器或候选邮箱时失败，不回退直接登录。

初始/重发响应只含 `{status:'EMAIL_REQUIRED', challenge_id, masked_email, expires_at, resend_after}`，时间由宿主转换为 ISO。`masked_email` 固定为 `***@***`，不披露邮箱域或本地部分；不带 token、code、真实邮箱或账号元数据。最终验证成功才返回原 token/user 结构。响应不缓存。

| 状态 | 含义 |
| --- | --- |
| 400 | 原始参数格式错误，或尚未耗尽的错误验证码。 |
| 401 | 挑战不存在、过期、已取消/消费、错误次数耗尽或凭证/邮箱已变化。 |
| 409 | 首次建立挑战时邮箱候选未具备核验条件。 |
| 429 | 时间窗口次数或内存容量已满。 |
| 503 | 发件器未配置/失败、基础服务不可用，或调用边界不符合约定。 |

核心 lookup 将 malformed/不存在的挑战统一为 401；HTTP 宿主应先把格式错误拒绝为 400。取消的 malformed ID 返回 400，合法但未知 ID 幂等成功。所有错误不回显邮箱、密码、验证码、来源材料或传输异常。

## 验证与剩余工作

`scripts/S01LoginVerification-check.sh` 编译真实共享源码，在脚本新建的临时目录使用真实 Auth、独立合成 H2、可控时钟及内存发件器；不会调用主 Db.init、读正式 app/data、读取安全存储、联网或发送邮件。JVM 启动前设置 data.dir，主入口验证临时目录标记、路径一致和目录为空后才接触 Db，初始化失败不调用 Db 清理。

专项覆盖正确/错误密码、零会话签发及核心数据库零写、单次消费、过期/取消、重发及全部限额、并发发送与账号/邮箱变化、凭证代次、旧历史完整性、重复邮箱、私密错误、明文验证码不落核心状态、时钟回退与容量不逐出。旧邮箱准备专项另行回归，确保原准备接口未放宽。实际结果记录在 S01 STATUS。

本轮默认生产发件器仍为空，未接实际 SMTP 或读取已保存凭据；用户提供的发件资料不写入这些文件。真实邮件送达、首次/新设备识别、设备信任期限及退出/撤销机制、正式启用账号与部署，仍由后续总控统筹，不属于本轮核心验收。
