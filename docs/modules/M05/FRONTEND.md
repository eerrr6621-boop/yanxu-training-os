## 内部演示与可复用逻辑

通过现有静态服务打开 `/modules/settlement/demo.html`。这是既有静态演示页，仅用于开发核验，不启动服务、迁移或生产连接；页面已明确标注“内部逻辑演示”，正式功能接回原“课程与排期”和“课酬发放”。

- 单位按用户明确确认采用 45 分钟/课时；页面统一使用“课时”和“元每课时”，避免与自然小时混淆。CSV 的 `*_hours / rate_per_hour` 沿用现有字段名，语义为课时及每课时费率，不是 60 分钟小时；分钟换算采用已确认的分钟÷45、课时显示两位小数；HALF_UP为明确记录的实现选择。该结果只作实际课时参考，不自动填入计酬课时；金额舍入仍待确认。
- “这份办法里的标准”是只读来源参考，按《金尊公司内部培训师管理办法2.docx》及 `POLICY_REVIEW.md` 展示4等级×4费率、45分钟/课时、研发团队成员授课及个人独立开发按讲师；明确标记征求意见稿、正式生效待确认，不提供启用或计费动作。来源表与下方合成记录分开展示。
- 下方演示授课记录中的编码、日期、费率与金额均为明确标注的合成样例，金额使用固定十进制字符串。政策表不参与合成预览、冻结或CSV；前端不使用 JavaScript Number 计算课酬。
- `conversion.js` 独立导出 `convertMinutesToClassHours(text, minutesPerUnit = '45', scale = 2)`，只支持45分钟及两位 HALF_UP，返回固定两位字符串。通过十进制字符串、BigInt商/余数运算得到课时，不计算金额。输入必须是 `[0-9]+(?:\.[0-9]+)?`、至多40字符/8位小数/24位有效数字；前导零不计精度，零精度为1；结果超过24位有效数字明确报错，不截断。
- “授课分钟转课时”仅作内部交互验证：默认60→1.33，90→2.00、67.5→1.50、0→0.00；空、负值及非法输入明确显示错误。修改输入先清除旧结果；换算不修改任何演示授课字段、冻结记录或计酬金额。
- 页脚已改成普通业务语言：现有办法已读取；具体计费不明确时以实际例子逐项确认；没有人力表先用系统编码清单继续，不索要整套材料。
- 三条授课记录分别展示未确认预览、已确认更正及缺规则状态；预计、计划、实际、计酬四类课时分别呈现，不能互相覆盖。
- V1/V2 切换仅选择固定的合成预览。点击“演示确认并冻结此结果”后，当前会话保存确认时的金额、四类课时及规则版本；切换版本保持原确认。刷新或重置会丢弃演示状态。
- 更正示例保留原确认 600.00，引用原记录生成替代结果 750.00，差额 150.00；显示编码、操作人编码、时间及冻结依据。该示例不擅定正式更正制度。
- 缺费率 / 舍入规则的记录显示“未配置”，金额保持空缺，确认不可用。
- CSV 导出全部合成记录（UTF-8 BOM、CRLF、引号转义、防公式注入），仅包含编码、业务 ID、四类课时与结果依据，无实名、联系方式、解码映射。原确认与更正分行，通过 `record_kind / replaces_settlement_code / status` 区分；原行 `settlement_amount=600.00`，`CORRECTION_DELTA` 行 `settlement_amount=150.00`、`confirmed_total_amount=750.00`，不把更正总额再次计入。未确认预览也显式标记，`settlement_amount` 与 `confirmed_total_amount` 均为空（页面可显示预览金额，演示确认后才填入导出金额）；缺规则行金额、费率和舍入为空。
- 无网络调用，无 localStorage / sessionStorage / IndexedDB / cookie 或生产写入。

## 正式模式边界

`mode: 'live'` 仅显示“正式接口未接入”，不展示合成记录、不导出、不确认。缺失或非法 mode 同样保持未接入状态。正式接口映射、权限判定、事实校验、计酬计算、冻结确认、持久化与编码导出须由总控接入服务后提供；不能拿 demo 作为正式验收。

前端需要接收服务端十进制字符串结果及规则 / 费率版本，不重算金额。四类课时、确认快照和更正引用应与 Java 核心及总控接口约定对齐；正式编码不可从合成示例沿用。
