### 数据、缓存和原操作保护

正式页面只调用原`api`封装与同一会话；权限在服务端按总控/M01策略校验，前端继续遵守现有`canWrite()`入口限制，不能将它替代服务端授权。页面/弹窗异步沿用`routeEpoch/isRouteCurrent/addRouteCleanup`，切换页签或关闭弹窗后取消未完成请求并拒绝迟到结果。

课程编码、判定日期、认证目录版本及本次明确条件须进入既有推荐草稿与`teacherRecommendationKey`；改动调用原`invalidateTeacherRecommendations`/dirty机制，阻止上次课程的结果被误当本次资格。仍保留需求双草稿、旧交通地点、最高课酬/严格预算和匹配前三规则，不另造一套推荐状态。新增资格不启用推断等级/城市门槛；认证更新后必须使相关推荐缓存失效。

具体状态接点为`teacherRecommendationKey:2599`、`persistForm:3617`、`markRecommendationDirty:3621`、提交控件锁定3760行、请求体3772行及响应校验3780行；新增课程控件须一并参加禁用/恢复与过期保护。缺少资格响应时，原卡片“未发现明显缺口”的兜底文案不得被解读为本课已认证：新增区域应写“课程资格未核验”，并将未满足或待核者置于原未推荐名单中的独立课程资格分组，不计推荐人数。

## Java 接口

```java
Map<String,Object> preview = CourseCatalog.preview(catalog);
Map<String,Object> qualification = CourseCatalog.qualify(catalog, request);
```

`preview.ready` 只表示本批结构/引用校验通过，**不是认定来源真实性、权限、持久化成功或正式准入认可**。有错误则 `data=null`，资格结果也不返回部分成功候选。警告保留在 `issues` 中，字段包括 `severity/table/row/field/code/message`；表内行号从 1 开始，批次/请求为 0。

`qualify.ready` 只表示该次明确课程条件可以计算。按讲师输入次序分成 `eligible` 与 `gaps`；两类都保留编码、等级、城市、认证证据，缺口含逐项原因。结果固定 `ranking_status=not_configured`。没有模型打分、交通推断、候选人数上限或排名。课程认证符合不等于整体派单准入。

```json
{
  "course_code": "DEMO-C01",
  "as_of": "2026-09-21",
  "accepted_levels": [],
  "allowed_cities": []
}
```

日期必须显式提供。非空等级/城市数组是本次精确允许范围，不推断等级高低、不转换城市别名；空数组表示本次未加该限制，不代表正式规则允许所有等级/地区。规则未提供时不自动生成门槛。

## 编码导入格式 v1

顶层精确字段为 `schema_version=m04_catalog_v1`、非空 `catalog_version`、`courses`、`teachers`、`certifications`。三张表每张最多 5000 行，所有行都参加校验，重复行不静默合并、不覆盖。多余字段（包括姓名、电话、履历字段）拒绝。当前支持 JSON；Excel/CSV 转换器和正式文件上传由后续材料决定，本轮不声称支持。

| 表 | 必需字段 | 约束 |
| --- | --- | --- |
| courses | course_code、course_name、active | 编码唯一；名称非空≤200；active 为布尔值 |
| teachers | teacher_code、teacher_level、city | 编码唯一；等级/城市是字符串≤120，空值产生未知警告 |
| certifications | teacher_code、course_code、status、source_ref、valid_from、valid_to | 必须引用本批讲师和课程；同一讲师/课程组合只允许一行 |

编码按字符串保留大小写和前导零；1–64 位，字母/数字开头，其余只接受字母、数字、点、下划线、连字符。不以姓名关联，不把编码强转既有数字记录 id。文本拒绝首尾 Unicode 空白、控制字符和格式控制字符，防止不可见来源绕过校验。来源引用≤240、目录版本≤120。

认证状态枚举：`certified`、`not_certified`、`unknown`、`revoked`。`certified` 必须有非空来源引用；`unknown`、无记录、未认证、撤销均不能算合格。来源应是可追溯的内部认定文件/记录编码，不提供实名映射。纯校验器只检查来源非空，**不会验证该文件真实有效**。

有效期必须为有效的 `YYYY-MM-DD`（0001–9999 年）或空字符串；提供两端时开始不晚于结束，起止当天都有效。认证未生效/过期列为缺口。空边界意味着“未提供该边界”，产生 `VALIDITY_UNSPECIFIED` 警告；只判断已给边界，不能解读为永久有效。正式业务是否必须提供完整有效期，待用户规则明确。
