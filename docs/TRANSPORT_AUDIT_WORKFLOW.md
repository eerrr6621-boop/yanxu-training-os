# 全国城市交叉核查与覆盖审计

## 当前任务：城市级公开参考，不要求用户提供时刻表

2026-09-08 用户再次确认：前期公开资料搜集由维护方完成，不需要实时余票、票价或面向用户展示具体班次，也不以提供接口文档或单位时刻表作为继续工作的前提。推荐查询复用已核的城市间参考时间；具体出行确认是另一个环节。

本文下方的 `TransportCoverageAudit` 是较早的**严格时刻证据审计**，不能拿它的车次字段要求阻塞城市摘要的整理。近期政府、铁路部门或运营方公开报道中的城市时间，可以按 [城市规划参考](CITY_PLANNING_REFERENCE.md) 独立核读和保存最小事实，保留方向、约数、来源日期和复核日期；不能复制单向时间充当返程，不能凭未查到铁路就启用飞机。明确禁止相应用途或访问方式的来源仍停止使用，不把网页可读当成全文转载或批量数据许可。

城市目录、已读线索、双向复核完成、已制备参考和线上已配置必须分别计数。检查的是规则 `<240` / `<180`，不是把所有参考都加上候车或接驳时间再缩小范围；实际行程所需接驳不能混入城市参考而不说明。

## 范围与验收口径

核查全集来自 `RegionDirectory.CITIES`，不读取讲师常驻地、简历、客户或分行名单。当前产品目录有 371 个省市组合；它包含部分县级直辖地区、盟和自治州，并不是“全国官方城市总数”。目录没有收录的地名仍需单独补目录，不能推断为不通车。

- 371 个目的城市，各自检查其余 370 个来源城市：137,270 个异地有向条目。
- 去返配对后为 68,635 个无向城市对。
- 另有 371 个同城条目；全部枚举输出共 137,641 条。
- 每个城市对需要两个方向的证据。一个目的地有三名老师，不影响其他城市继续核查。

**生成了待查条目，不等于查过了时刻表。** 脚本不发网络请求，只按输入来源计算哪些已满足现有规则、哪些仍待人工取证。

## 来源许可与停止条件

**先确认许可，再开展取证；规则校验通过不等于获准用于业务。** 公开页面可读，不代表允许批量获取、复制、长期保存、再分发或商业使用。开始新增取证前，须确认来源条款或书面授权覆盖计划的采集方式、保存方式和业务用途，并保留授权依据。

- 发现来源限制、权限缺失或用途不明确时，停止该来源的新增取证和业务导入，等待适用的数据许可或明确允许该用途的数据源；不通过换抓取方式、人工转录、缓存或更换 URL 绕过限制。
- 研究材料与生产配置分开保存。隔离的研究输入不得随仓库、构建或部署发布，也不得因审计出现 `eligible` 而自动合并进业务交通表。
- 本脚本只验证交通字段和现有算法规则，**不验证数据使用授权**。包括名称中含 `production` 的输出字段，也只是生产解析器的计算结果，不是业务批准、来源许可或上线凭据。
- 历史主表同样需要独立核对来源许可；本文不对已存在的数据作“已经获授权”的追溯认定。研究读取和复算也必须位于获准的用途范围内。

## 执行流程

1. 先完成来源许可审查；若不满足上面的条件，则停在此处。通过后，为来源城市与目的城市逐向核对获准使用的时刻资料，记录车次、站名、出发/到达时刻、运行分钟、页面查询日期、观察日期与链接。
2. 将明确的方向证据放入私有研究批次 `directions`，或 `cities[].directions`；单向有效记录也可保留，缺少反向仍为待核查。`pending_city_reviews` 等说明中的示意或过期观察不会自动提升为正式输入。
3. 在获准范围内运行覆盖审计。铁路、航班、完整排除证据仍由生产代码验证，不以研究批次标题或城市状态代替字段验证；审计不执行许可检查，也不自动批准导入。
4. 按每城市 `next_verification_queue` 补齐缺项，再生成一个新的审计目录。队列优先级是工作优先级，不是交通就近排序，也不是限定核查范围。
5. 铁路满足双向 `<240` 分钟的，在本次输入范围内标记为通过铁路规则；是否可用于业务还要经过来源许可与导入审批。慢车样本、没有搜到车、单向记录或过期结果均不足以证明“铁路超过四小时”。只有生产规则接受完整铁路排除证据之后，才能考虑双向直飞 `<180` 分钟的航空参考。
6. 发布或实际排课前仍核实授课日运行、市内接驳、候乘、值机安检和到课可行性。参考准入不等于已确认行程。

## 输出状态

| 状态 | 含义 |
| --- | --- |
| `same_city` | 同城，市内通勤和档期仍未核对 |
| `rail_reference_eligible` | 生产解析器接受双向近期铁路样本，均在当前上限内 |
| `air_reference_eligible` | 生产解析器接受铁路排除依据及双向近期合格直飞样本 |
| `outside_verified` | 生产解析器接受完整铁路及航空范围排除依据；不等于完全无法抵达 |
| `pending_missing` | 缺少可用来源，或来源记录明确标为尚未核实 |
| `pending_oneway` | 目前仅一个方向存在合格铁路样本 |
| `pending_stale` | 日期过期、超前或格式不能确认，不能作为当前依据 |
| `pending_slow_sample` | 只有不满足阈值的列车样本，不能证明没有快车 |
| `pending_incomplete_exclusion` | 铁路/航空完整排除条件尚未被生产解析器接受 |
| `pending_invalid_evidence` | 记录声称有样本，但站点确认、时刻差等必需字段不通过 |
| `pending_policy_limit` | 当前管理员跨城上限暂停或收紧准入；不等于交通不存在 |

同一路线可有多个 `reason_codes`。例如一向有效、另一向过期，主状态为 `pending_oneway`，原因中同时保留过期标识。保留 `production_status`、`production_eligibility` 便于复查；审计细分原因不会推翻生产准入判断。

## 运行

从仓库根目录运行。使用现有 Java 17 与仓库 ECJ；不需要安装依赖，也不改服务端源代码。

下例只审计显式指定的现有主表，不默认加载研究批次。执行前仍须确认自己有权读取和处理相应输入；命令能运行不是来源获准的证明。

```sh
AUDIT_WORK="$(mktemp -d /private/tmp/yanxu-transport-audit.XXXXXX)"
$HOME/.local/bin/java -jar lib/ecj.jar -17 -encoding UTF-8 \
  -d "$AUDIT_WORK/classes" -sourcepath src scripts/TransportCoverageAudit.java
$HOME/.local/bin/java -Xmx512m -Ddispatch.nearby.max.minutes=240 \
  -cp "$AUDIT_WORK/classes" com.training.TransportCoverageAudit \
  --rail-file config/rail-timetable.json \
  --today 2026-09-07 \
  --output-dir "$AUDIT_WORK/audit"
```

正常使用可省略 `--today`，采用北京时间当天；给定日期用于可重复审计，并不是改写来源日期。`-Ddispatch.nearby.max.minutes=240` 仅设定本次独立进程的核查上限，不修改线上配置；输出会记录实际使用值。`-Xmx512m` 是 Java 堆上限，不是进程总内存测量。

可选参数：

- `--transport-file PATH`：显式指定 `transport-matrix-v1` 数据，包含 `rail_directions`、`rail_checks`、`air_checks`、`flights`；不默认加载任何私有配置。
- `--research-dir PATH`：可多次传入，支持顶层 `directions` 或 `cities[].directions`。只扫描该目录直接包含的 JSON，不递归读取其他资料。
- `--cross-check-all`：每一个条目同时比较索引后与全量输入的 `TravelMatrix.resolve` 输出，验证索引没有改变结论；数据量大时只用于验收。
- `--verify-catalog-city 江苏/南京`：与 `DispatchPriority.catalog` 对照该目的城市的全部目录条目，可多次传入。此模式要求已合并的 `--rail-file`，不与 `--research-dir` 同用；明确将机构文件设置为不存在路径，不读取用户机构资料。

输出目录必须是新建的私有临时子目录或 `.codex-tmp` 子目录；若已存在则拒绝覆盖，`web/public/dist/static` 路径拒绝写入。审计结果不能当作生产交通矩阵直接导入。

**可选的隔离研究模式**：只有已确认允许该研究处理时，才在命令中另加 `--research-dir /absolute/private/path/to/permitted-research-batch`。这里是必须由操作者替换的绝对私有路径占位符，不是仓库目录。应使用另一个全新的私有输出目录，并将结果标为研究复算；业务使用权限尚未获得时，不得把复算结果用于推荐、排课或发布。

## 文件结构与安全性

- `summary.json`：总分母、输入在现有规则下的通过数、待查数、输入文件哈希、执行类哈希及各城市下一条待查任务；不包含来源使用许可判断。当前脚本的汇总和城市文件固定标为 `PRIVATE_AUDIT_ONLY`、`commercial_permission_validated=false`、`business_import_allowed=false`。
- `省份-城市.json`：该目的城市全部 371 条记录、状态计数、来源日期、去返样本和完整待查队列。
- 未满足条件的条目继续保留在输出中，不因缺老师、没有历史项目或来源失败而被删掉。
- 输出只保留交通来源必需字段。来源 URL 去除账号信息、查询串及片段，避免复制接口参数；保留的链接和来源输入哈希用于复核。
- 不读取机构、讲师、数据库、密钥或服务端默认私有矩阵。没有登录、网络请求、生产写入或自动部署。
- 输入按城市对建立索引，调用原始 `RailTimetable.direction` 与 `TravelMatrix.resolve`；不循环扫描整张来源表决定每个条目。
