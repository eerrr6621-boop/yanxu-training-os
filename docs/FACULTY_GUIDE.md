# 师资简历与推荐使用说明

登录系统后进入“师资资源”。系统管理员和业务管理员可使用“师资库”“简历管理”“智能推荐”；只读账号保留基础师资档案查询权限。

## 建立讲师档案

1. 在“师资库”点击“新建讲师档案”，可先凭姓名保存为**待完善**，再补充机构和专业领域等已知资料。录入、编辑及“常驻地区”操作均提供常驻省份、常驻城市 / 地区入口；未知的地区、课酬和讲师等级留空，不必填0或模拟信息。
2. 在“简历管理”选择对应讲师，上传 PDF 或 PPTX。PDF 最大 15 MiB、50 页，PPTX 最大 200 MiB、100 张幻灯片。
3. 打开“解析详情”，核对专业主题、行业、授课对象、资历、课程和客户案例。简历中的授课量、满意度等标为“简历自述”，不能替代实际交付记录。
4. 需要修正时编辑“人工专业画像”。它是管理员确认后的专业描述，保存前应保留仍然有效的课程、行业和能力信息。更新简历原件或重新解析时保留人工校准内容。

简历原件属于内部师资资料，不会出现在免登录的培训资料下载中心。图片型、扫描型或文字不足的文档会提示人工补充画像；当前版本没有 OCR。

**待完善档案可以先上传原件并解析，不参与推荐或调度。**补齐经讲师确认的常驻省市后，使用“完善并入库”；单独保存常驻地或上传简历不会自动入库。只需常驻城市，不需要家庭地址，不根据单位名称或简历自动猜填。

旧在库档案不会被虚构地区覆盖：在师资库可单独“常驻地区”，其上传简历和保存人工画像仍须填写真实常驻省市。历史排课、出入库记录和重解析不因缺地区被锁死；尚未补齐的旧老师可作为待核对候选展示，但明确标记常驻地待补充，不参与同城优先。省市提供联动候选；字典未覆盖的新地名可手填，核对前不参与同城优先。字典来源、日期与限制见 [地区数据说明](REGION_DATA.md)。

人工画像与常驻地区在一次事务内保存；如果简历已被其他管理员替换，不会只保存地区造成部分成功。上传前若修改了地区，会先保存确认的修改再上传；文件失败但地区已保存时，界面会分别说明。待完善档案可继续保留未知城市，不需要为上传而猜填。

## 投标前推荐与调度参考

业务顺序是 **客户需求 → 投标前师资推荐 → 人工核对候选与客户意向 → 投标 → 中标立项 → 排课交付**。推荐不能代替中标立项；本轮提供需求行的“推荐师资”入口，带入需求与调度条件，不自动创建项目、排课、课酬，也尚未新增“客户确认候选方案”的持久化流程。

- 以匹配前三为目标；**第三名的整数匹配分相同则全部保留**，不截断并列讲师。旧客户端传入 5 / 10 / 20 也不会改变前三规则。如果不足三位，显示实际人数、缺口及内容或交通原因，不放宽专业依据、当天档期或硬性预算来凑数。
- 客户授课省市、线上 / 线下、上午 / 下午 / 全天独立填写，两种需求输入方式共用；不从项目地址或正文猜填。改条件后旧结果失效。未确定地点或方式时不启用地区排序。
- 线下且地区已识别时，**同城及所有已证实双向铁路小于4小时的城市统一进入比较范围**，不会在2/3小时层够三人就停止。圈内按模型分、同分等级、末位并列全留。铁路不足时才补充双向直飞小于3小时的航空后备，航空不挤掉已有铁路候选。线上或关闭地区偏好时，不按地区缩小范围。
- 同城优先分 100；去、返程取较长一程，铁路站到站样本 120 分钟内 85、180 分钟内 70、其余不足 240 分钟 55。分数只划定完整比较范围，不与模型分相加。240 分钟是业务上限，恰好 240 分钟不入铁路范围；可配置降低或设 0 暂停跨城扩圈，不是交通测量。未知路线、超限或实际出发地不明进入“交通待核实”，不凑三位。**不使用城市坐标、直线距离、公里除以速度估算高铁时间。** 接驳、候乘、具体授课日班次和到场可行性单独待确认，不因缺这些资料而否定已有站到站参考。
- 选择授课城市后，可展开“查看机构与高铁时间优先级”，查看当前字典全部371城的已解决/未知计数，以及去返程车站、车次、分钟数和来源。铁路慢样本不能证明没有快车；未知城市不能消失，也不直接转航空。全量时刻数据尚未取得，清单齐全不代表时刻已查全。当前规则与接入边界见[v7交通覆盖](TRANSPORT_COVERAGE_V7.md)。
- 新增、编辑讲师可选独立“讲师等级”：讲师 < 高级讲师 < 特级讲师 < 特聘讲师。已有档案保留未填写，不根据职称或简历自动赋级。池内模型分相同才按等级高低排列，等级不加分、不影响第三名模型同分全部保留。
- 异地不按同省判断更近，也不生成虚构交通数据。结合“调度表生成”的原则：核对往返耗时、车票、市内接驳、住宿、餐补和总差旅。早课或全天异地授课提醒提前一天到达，并检查前一日已有课程；前一天有课提示衔接待确认，不武断认定无法到达。下午课提示核对当日往返方案。
- 具体车次、单程两小时、票价约 100 元等约束必须有可信交通数据及本次任务确认后才能作硬筛选；当前未接入实时交通，不能宣称已核实可达。无系统排课不等于老师已确认有空。
- 新排课和需求保存规范为 ISO 日期；推荐兼容历史有效的非补零日期和首尾空白。无法解析的历史排课仍需人工校核，不能当作可用证明。

推荐规则版本为 `local-v7-all-cities-rail-air`，简历解析版本仍为 `local-rules-v2`。本轮在本地隔离库验证，未发布生产，航空数据源尚未开通。可选本地语义辅助默认关闭；不是自动差旅报价。[v7当前状态](TRANSPORT_COVERAGE_V7.md)与[v6历史记录](RECOMMENDATION_V6.md)分别保留，v5真实简历结果仍是历史基线。

### 可选语义辅助与具体授课时间

管理员启用本机语义服务后，对通过在库、预算、排期硬筛选的讲师进行语义比较，再检查已识别的课程内容是否有逐项原文依据。部分内容缺证的候选单列，不用综合相似度填补缺项。人工画像优先，不重新并入被删掉的旧画像。未配置、超时、繁忙或证据无效时整批移除语义维度，使用本版证据规则；不混用半批结果。详见 [本地语义辅助说明](../semantic/README.md)。

模型匹配分为 `round(100 × clamp(相似度, 0, 1))`，不混入等级、就近分或旧规则权重。未启用或模型失败时显示“模型未评分”，仅提供明确标注的文字依据参考顺序，不伪装成模型零分。模型分仅比较本次需求与资料文字，不是授课能力认证、胜任概率或系统履约评分。明确原文依据不因 0.62 这样的相似度门槛消失；语义相关但缺少内容依据者仍单列待核对。

若同一个铁路池只有部分老师获得模型分，未评分老师单列“模型待评分”，不以规则分混入模型排名，也不会因此跳过他们向航空凑数。补齐评分后再重新比较。航空须先具备完整铁路范围核对结论，不能因为没查到铁路或只有一个慢班次就启用。

可以选填授课开始、结束时间，二者须一起填写且有明确日期。已有安排时段重叠或时间不明的老师不会通过该次时间筛选；不填时间仍按整日检查。前后一天的课程会列作调度核对事项，**时间不重叠不代表能赶到**。同城依据确认过的常驻城市，不代表老师当前就在该地。

当前目标不依赖实时余票。站到站时刻来自公开供应商页面，双向独立核对；观察日期与网页查询日期分别保存，不冒充运行有效期。已知任一日期超过 30 天的样本不再自动参与初选；来源完全未标查询日期的，显著提示并按观察日 30 天要求复核。不自动刷新、订票或排课，接驳、实际出发地和授课日行程仍需确认。

## 输入客户要求并筛选

可以直接输入客户原话，也可以从已有培训需求带入后修改。提交时以页面当前显示的要求为准。

建议写清培训主题、客户行业、参训对象及需要核对的实际经历，例如：

> 某银行希望为网点大堂经理开展客户投诉沟通与服务礼仪培训，希望老师做过银行分行的服务资格认证课程。

如有课酬限制，单独填写“最高课酬（元/课时）”。项目总预算还包含差旅、物料等成本，不能直接当作每课时课酬。需要严格限制时勾选硬性上限。

结果展示匹配理由、专业依据、待确认事项和系统履约记录。没有相关专业依据时不会为凑足人数而推荐。明确日期存在已有排课，或触及硬性课酬上限的讲师会在排除原因中说明。地区、差旅、复杂否定条件和个性化要求仍需运营人员与讲师确认。

本版采用服务器本地专业标签和文本匹配，可选启用离线小模型辅助排序，没有接入外部大语言模型。匹配分用于比较现有档案与本次要求的契合程度，不是授课成功概率，也不是对讲师教学质量的定论。简历越完整、人工画像越准确，推荐依据就越充分。

## 累积授课记录、场次和评价

在“课程与排期”记录实际授课，并在授课完成后使用“完成”操作。每条已完成授课记录计作一场，课时按该记录累计。未完成或仅确认的排课不会进入已完成场次。

在讲师档案中查看授课记录，并对已完成授课所属项目录入师资评价。推荐页显示评价均分和评价份数；尚无评价时显示缺少数据，不用简历自述的满意度代替。当前评价采用 5 分制，不能把它直接解释为满意度百分比。

未来如需导入系统启用前的历史场次、调查满意度、参与人数，应记录来源、日期、课程或项目、评价量表与样本数，并避免与已有排课重复计数。请勿把历史总数直接写入专业画像来充当系统实绩。

## 维护原则

- 更新简历前确认关联的是同一位讲师；同名讲师用机构等信息区分。
- 定期核对专业画像、在库状态、课酬和档期；出库讲师不参加推荐。
- 推荐只生成供运营人员选择的候选，不自动创建排课。
- 删除简历不会删除讲师基础档案、授课记录或评价；原件和该简历的解析内容会被删除。
- 每次版本更新运行隔离回归，覆盖上传与权限、专业匹配、人工校准保留和实绩口径；真实简历与正式账号不得进入公开仓库。
