# 来源字段绑定的授课事件：第一阶段，未部署

本次建立一条共同的事件数据结构，让显式字段块中的课程、授课人、角色、完成状态、对象、形式与数量保持同一来源范围。不是新模型，不宣称解决任意自由文本，也不改变“简历自述不等于资质认证”。

## 已实现

`TeachingEvents` 识别以课程字段起始、按行填写的明确事件块；换课程、空行或章节边界结束一块。只有包含主体、角色或完成状态字段的块才接管原来的散行匹配，其他自由文字仍走原路径。

每个事件保存 `source_teaching_event_v1` 版本、事件 ID、课程及其他字段、每字段原值、完整连续正文、Unicode 码点位置、未承载上下文和冲突原因。正文为 NFKC 规范化版本，位置不冒充 PPTX/PDF 原件字节坐标。

- 本人主讲和明确已完成状态共同成立，才产生个人已完成授课自述；主讲人标签可明确主体和角色，课程目录不证明已授课。
- 相同别名字段值冲突、缺必要字段、助教/同事主体、计划状态不能借另一课补齐。
- 内容与条件检查直接消费同一事件字段，不把字段拼成改写的证明原文再重复猜测角色。
- 对象、形式、语言、完成场次及每场时长须在同一对应事件内成立，不能从同名但不同场次中各挑一项；累计时长不能证明每场时长。
- 只有明确 `每场时长` / `每场活动` 字段才支持对应逐场约束；课时不擅自折成45或60分钟。
- 相关条件保留 `source_event`；完整事件及字段来源可在响应中复核，`verified` 仍为 false，未调用模型时不制造分数。

## 上下文边界

独立检查发现：前文说明表格属于同事、前文说明只是未举办活动的模板，或空行后的更正，都可能改变“本人”的含义。因此块外未解释文字进入上下文账本，不能在解析字段时丢弃。

目前自动接受的结构化块要求其块外语义上下文可承载；纯符号装饰及已识别的个人资料标签不当作授课断言。未知说明使该结构化块待核，不用一张完整表掩盖未解决的语境。其他独立非结构化证据并不由此整体删除。

这是保守的第一阶段：混有自由叙述的复杂简历仍可能需要核对；尚未实现任意指代、叙事事件或同义课程的通用解析。不能将此限制包装为“所有简历都理解准确”。模型端与服务器端的完整事件协议仍需后续统一验收。
