# 二十轮准确性与调度验证

日期：2026-09-07。结论：**交通规则测试通过；师资匹配尚未达到可宣称精准的程度。主要缺陷在同义需求准入和硬性要求识别，不是本轮量化损失。** 没有训练、调参、修改生产匹配代码、替换模型、推送 GitHub 或部署。

原精度 FP32 与量化 INT8 在 72 个构造案例中，**正式推荐集合全部相同**，仅一题的排列先后不同。两者正式精确率同为 65/76；原精度首选 56/64，量化版 57/64。不能因此断言量化提高了业务质量，只能说这批问题不能归因于量化。

## 已定位的错误

1. **模型找到，规则拦住。** 同义题 8/8 原始模型首选正确，但 7 条需求未触发词表或整句匹配，因此正确讲师不能正式入池。历史的银龄客户金融安全需求也出现相同问题：相关证据已经解析，模型已评分，但主题未识别，最终返回空。
2. **漏识别一项要求，导致部分满足也入选。** “财税实务”是分类名称，却未进入该分类的识别词；在与服务礼仪、AI、劳动用工并列时，程序只核对剩余识别到的模块。构造案例 S04-01、S04-04、S08-03 均复现。提高相似度不能修复这个准入缺口。
3. **主题符合被当作额外条件也符合。** 教学方式、对象、授课年限等没有完整逐项核对。第 7 轮首选往往正确，但要求推荐三位时仍会混入证据不足者；要求本人主讲的题仍接纳了机构客户陈述，至少三年的题仍接纳了首次授课记录。第 3 轮明确措辞的 8/8 不代表所有授课角色表达都已解决。不能只优化第一名而忽视整组名单。
4. **真实简历的正式/备选边界仍需业务确认。** 亲子财商需求返回 5 位（第三名整数分并列），其中 3 位按此前冻结标准应列备选。该题未明确要求已发生授课经历，这些简历也有相关能力自述，因此不能据此说三位老师实际不会教。这里是相对严格标签的边界失配，需要明确业务标准，不能为了提高成绩临时改标签。

72 个构造题里，72 个严格相关“需求—人选”组合有 65 个进入内容准入范围，准入召回 90.3%；余下 7 个均为同义题。这与最终只取前三的正常截断不同。真实 API 未暴露全部内容候选名单，因此不据返回名单反推真实简历的完整检索召回率。

## 对后训练的判断

可以尝试小模型的需求—正例—难负例对比微调，但**先修证据与准入，再训练排序**。否则模型即使排对第一，也仍被现有规则排除；只提高分数还可能把证据不足者一起推高。

建议顺序：修复完整需求识别和章节/角色证据 → 明确正式/备选的业务标签 → 另建经授权的训练/开发数据 → 保留新讲师、新需求独立测试 → 对照原版和微调版的 FP32/INT8 → 达标后再灰度替换。此次测试集不回灌训练来制造成绩提升。

训练类型、数据授权、依赖、衍生版本、缓存隔离和发布门槛见[后训练方案](SEMANTIC_POSTTRAINING_PLAN.md)。本轮没有建立或更新任何模型权重，也未实测训练速度或费用。

## 方法、隔离与复现

- 9 轮构造题在首次推理前固定，独立复核了标签与证据范围。与此前已见的 8 条真实简历需求分开报告；重复主题变体不是独立用户样本，不给出虚假的统计置信度。
- 新探针调用当前有效画像、全部候选语义比较、`RequirementCoverage.assess`、`NearbySelection.select`。没有沿用旧诊断器的模型前标签过滤或旧排序，也没有用一套另写的推荐器代替实际代码。
- 同一组构造题分别跑 FP32/INT8，模型全部 72/72 ready，未出现超时或规则降级冒充模型成功。计时包含缓存影响和小样本，只是本机诊断，不是服务器 SLA。
- 第 9 轮仅验证 8 组以独立句显式标出的性别/年龄及非专业表单字段变化，不证明简历中的所有叙事性个人信息均不会影响分数；这类信息仍需更完整的脱敏与专业证据切分。
- 第 10 轮先在全新隔离库录入 19 名 `【灰度测试】` 讲师，再上传用户之前指定的 19 份原 PPTX；随后建立 8 条同样标记的需求。19 份均解析完成，8 次真实模型请求均 ready；推荐前后核对未新增投标、项目、排课和课酬。
- 所有原简历、解析正文、身份映射、API 完整响应、缓存和数据库留在私有测试目录。仓库报告只有匿名数量、代码摘要和构造题 ID。未改线上业务数据或现有常用预览。
- 生产源文件全程冻结。重新编译全部源码，与实际执行的 54 个生产字节码文件逐一 SHA-256 比较，相同；冻结摘要见[匿名机器报告](../semantic/reports/twenty-rounds-v7-20260907.json)。
