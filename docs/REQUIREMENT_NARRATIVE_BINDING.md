# 自然需求中的课程、对象与授课经历 · 2026-09-08

这项修复针对需求语法，不是后训练，也不修改向量模型或讲师评分权重。它不能验证履历真实性；只负责将需求中确实表达的条件送入原有证据与准入检查。

## 处理范围

`RequirementNarrative` 从原文连续跨度区分请求者、授课对象、教学动作和课程。例如“服务站要给新员工补一堂线路排查课”，课程是线路排查，对象是新员工。没有课程实体时不猜测；多门课与单一回指不相容时保留待核。

“招聘给新员工讲竹编收口的老师”中的招聘是寻找讲师的动作，不是岗位招聘课程；只有课程本身是招聘面试时才仍纳入对应专业主题。面授等形式仍作为条件保留。

“以前确实为这类新人上完过这门面授课、整堂由自己讲”只能绑定唯一的前文课程与受众。资深主管不能被“这类新人”悄悄替代；“刚入职/新入职”的语法变体可对应，但岗位、单位、资历修饰不能被抹掉。“单位办过班不能代替本人经历”“单有写教案的成果还不够”仍要求本人实际授课证据。

## 独立审阅发现并修复的问题

1. **事务被当成课程。** 旧新增语法会把“我们需要给甲方安排付款的老师”错误提取为付款课程。修复以动作—宾语结构区分：安排、开展、开设等通用动词须有课/课程后缀，或一堂/一门这样的教学量词；仅有“的老师”、一次/一场不足。没有设置付款等业务禁词。
2. **未解析的排他条件没有参与准入。** 当主题已被识别，“只要给飞行员授过课”“本次课仅用于飞行员复训”曾只留在原文记录而没有形成硬约束。现在未由明确语法承载的只要、仅限、仅用于、唯一、只能等限制进入待核条件，实际阻止自动准入，而非只保存文字。

原失败结果保留于私有审阅目录；新测试不覆盖旧结果。单元测试使用多个无关的合成课程主题、角色与完成状态对偶，以及完整 Coverage 判定，并检查原文跨度。测试中固定结构化事件用于隔离需求侧问题，不代表模型准确率。

## 验证边界

后续历史回放还发现“岗前课”被误当独立专业。未用书名号明确命名的岗前、入职、复训等
现在保留为培训阶段上下文，不凭空添加专业主题；有具体训练内容时仍逐项核对内容，
只有阶段、没有实质主题时保持待核。显式《岗前》仍按用户实际课程名称处理。
受众不随阶段一起删除；类型比较通过共享 `AudienceContract`，详见 `AUDIENCE_CONTRACT.md`。
