# 公开城市通达参考（未部署）

目的：由本项目前期搜集近期公开交通事实，长期复用于投标前师资初选。用户不需要提供时刻表、实时票务 API 或具体班次；本功能不估算直线距离、不查询余票。

## 与已有数据层的区别

`public-city-travel-reference-v1` 是独立整理的公开事实摘要，不冒充授权时刻表或人工审核。既有 `city-travel-reference-v1` 人工授权库保持不变。公开可读不等于拥有复制整套商业数据库的许可；受限接口、明确禁用资料、旧 research_only 数据不通过换 schema 自动准入。

运行时只读取配置的本地文件，不联网搜索、不调用模型计算交通时长。独立配置：`YANXU_PUBLIC_CITY_TRAVEL_REFERENCE_FILE` / `YANXU_PUBLIC_CITY_TRAVEL_REFERENCE_DIR`，或 `dispatch.public.city.references.file` / `.dir`；默认空。目录形式使用授课城市 `省份-城市.json`。目前未配置到生产。

## 明确的准入规则

- 去返方向分别有证据，铁路每向严格小于 240 分钟；239 分钟可进范围，但显示边界复核提示。铁路未查齐不等于铁路不满足。
- 航空仍需双向直飞各小于 180 分钟，并有完整双向城市铁路排除依据。单站对最快、单条慢车、未找到路线均不能作为排除证明。目前没有真实公开航空准入记录。
- 单个站对的小于 4 小时见证可证明该城市对存在符合范围的铁路参考，不代表该时间为全市最快或包含市内接驳。
- 保存原发布时间、实际开通时间、阅读核对日期及站点。重新阅读旧新闻不得变成新的交通有效日期；跨库冲突待核，不拼接不同库去返最短值。
- 公开证据可为已开通后的报道，或明确实施日期已经到达的正式定期运行图公告；两个状态分开保存。原发布不超过一年，一次整理后的复核期默认90天、最多180天。旧事实仍保留，不在过期后自动刷新日期。参考可在复核期内长期重用，不要求每次推荐联网查询班次。

## 已生效公告参考

`service_state=published_schedule_baseline` 专门保存“正式公布、已经到实施日期”的定期运行图，不冒充 `operating` 的事后开行报道。它仍是来源核对后的基准，不证明授课当天运行情况。

- 必须为铁路定期运行图，同份来源中的明确实施日期与资料日期相符；发布日期不晚于实施日，实施日不晚于调研日。不把拟建铁路、待批准方案或未来日期当成已生效。
- 原有 `operating` 分支仍要求事后来源；不能只改状态字符串跳过日期证据。
- 明确撤销、停用、已被替代、限定有效期已结束或临时产品不准入，资料核对日期不能覆盖这些事实。
- 同一公告明确“往返……的标杆列车”及每趟全程时长，可以支持双方向；这是一个明示双向产品，不是把单向最快值镜像，也不能说成两个独立实测来源。往返合计、仅去程最快、约数或混合站对不按这种语法准入。
- 标杆产品只证明相应站对有通达参考，不能扩大成所有班次、全城市最快或完整铁路排除。

前端逐向显示“已生效运行图公告参考”、公告实施日期、原发布和调研日期，保留非当天行程提示。公告与路线的适用关系仍须在实际资料整理时核对；同URL本身不是关系证明，也不能证明页面真实性。

## 来源绑定

每条证据保留短原文断言及其 UTF-16 起止位置。自动验证要求 `original_content` 中断言之外只有标点或空白；另有前后文字说明时须待核，不能只选择肯定子串。断言须是完整子句，起点、终点及一个明确时长必须属于同一方向；未知句式保留待核。明确规划、临时或停运不能被 `operating` 标记覆盖。证据、引用、全库的撤销和禁用均受检查。

两类受支持的时长依据：

1. 原文直接说明一个明确有向时长。
2. 同一已公布行程的出发与最终到达时刻之差，要求角色明确、完整站点词、站序和时刻单调、同日连续运行。到达站名后的换车等残余叙述不得吞入站名。不把到站时刻当离站时刻，不把不同列车拼接，不处理未证明的跨日情形。

站点属于哪座城市仍须独立核查。`city_mapping_checked=true` 只记录整理决定，不是联网查证工具；当前没有完整全国站点归属字典，不能靠这一布尔值证明任意站点映射正确。独立追加的错误归属探针仍暴露该边界；已制备的京津条目端点另经实际来源复核，不代表全国映射已完成。

完整城市铁路排除需要原文明确覆盖两市全部车站和全部铁路路径，不能只填 `coverage_complete=true`。语法验证只是阻止错绑定，不认证网页真实性；实际来源核对仍须保留。

## 制备与验收

`scripts/PublicCityReferencePrepare.java` 接受明确整理的 JSON 草稿，只填内容哈希和首个审计事件，然后调用业务验证器验证正反两向。输出路径须为新文件，不覆盖已有版本、不写生产配置、不代替来源核对。内容哈希是完整性记录，不是授权或人工签名。

本次首个真实私有制备样例是北京西与天津西：按 2026-01-27 实际开通报道的同一行程端点时刻，正向 110 分钟、反向 122 分钟。它证明一个符合 4 小时范围的站对见证，并非北京—天津最快值；首次双向业务解析通过，尚未部署。来源：[北京市人民政府门户网站](https://www.beijing.gov.cn/fuwu/bmfw/sy/jrts/202601/t20260127_4468381.html)。

另一个私有样例为汕头—广州东：2026-01-16正式公告明确1月26日新图中的往返标杆产品，每程110分钟；保存为已生效公告参考而非9月开行核验，正反业务解析通过。来自一个双向产品，不累计成两次独立调查，未部署。原公告站名“汕头”“广州东”原样保留，地理归属另查政府资料；不是全城市最快值。[广州市政府公告](https://www.gz.gov.cn/zwfw/zxfw/jtfw/content/post_10648700.html)

合成证据、跨库冲突、用户边界、缺返程及真实公开样例分别验证。资料搜集数量、已核对双向数量与生产启用数量须分别报告，不能把研究观察条数写成全国覆盖。
