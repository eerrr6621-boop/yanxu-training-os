# 引导字段重复待核门禁的有界修复

本轮是需求输入接口修复，不是新模型训练、自然语言全解析或部署。原有 8 字段契约和原始字段账本不变。

## 问题与实测

原 `RequirementInput.annotate` 对所有非空 `preference` / `extra` 再附一个整字段待核项。因此同一条已闭合、且已有证据支持的显式适配要求，从纯文本提交能够推荐，从引导表单提交却再次被整体待核。两个独立合成领域的真实前端 renderer → HTTP → Coverage 对照复现了这个差异。

旧类运行新迁移断言：55 项中 2 项失败；首次修订仍有同样 2 项失败。原因是内容检查选中了档案专业标签，对象检查选中了另一条完整个人记录，不能要求这两个显示引文完全相同。最终改为复用当前完整有效匹配源中的单元与既有同课程作用域判断，迁移回归 55/55 通过。原 55 项测试文件保持原字节，对原类仍 55/55 通过。

## 限定行为

只有以下两类完整单字段可以撤去重复整字段门禁：

- 已有 `teaching_history_condition` 的完整来源跨度覆盖该字段，唯一课程绑定及原 `source_supported` 经历检查均成立。
- 完整闭合的明确对象适配条件，原对象检查已为 `source_supported`，同时由既有 `featureScoped` 或 `TeachingEvents` 证明同课程、同有效源单元的对象关系。

不新增主题词表。仅省略字段首尾空白和末尾句号等已限定标点；未知资格、日期、多句、额外并列条件、多课程仍保留整字段待核。此处不另造授课形式解析器。

`annotate` 从不把 `_admitted` 或 `coverage_complete` 改成真，也不改变原覆盖检查状态。它只决定是否附加自己的重复门禁。新增候选级 `requirement_field_assessment` 记录撤去原因、完整规范化字段跨度、对应课程、支持条件和当前源单元身份；`unresolved_guided_fields` 保留其余字段。共享输入账本仍是原始输入分类，不被某位候选的证据反向改写。

## 证据边界

`TeacherIntelligence` 只把与前一行 `Coverage.assess` 相同的现行 `semanticTexts` 传入新重载，保留人工画像删改的权威边界；不读取或回填历史简历。旧无源重载保持保守待核。

显示引文必须与当前完整源重新提取的唯一原文单元完全相同，且原始偏移可逆。已有不完整文档范围先独立验证；混合范围继续使用原 `mixedEvidence` 安全视图，其他范围只能选择一个已验证范围内的真实单元，不能拼接后重新绑定。短于 220 字不等于完整：219/220 字完整单元可核验，221 字被截成 220 字的引文不能核验。省略号、不同位置重复同文引文、错误版本、全文否认或人工删除后的旧引文均不能撤去门禁。

## 验证范围

新纯测试 `RequirementInputResolutionTest`：202 断言通过；另外六组未改的既有需求/受众/证据测试共 638 断言通过，总计 840。新 HTTP 迁移副本 55/55；旧 HTTP 原类基线 55/55。只用合成资料、新临时数据库和本机回环服务，模型运行次数 0，未触碰生产或真实简历。

旧 HTTP 文件中的两条“完整适配要求仍应整体待核”断言刻画的是本次修复前行为；保留原文件，另加迁移副本改变这两条预期。没有修改旧评测题、训练标签或旧报告，也未修改 `check.sh`。

## 未解决范围

这不是任意自由文本都能自动消除待核。多课程、复合条件、未被既有解析器完整识别的历史表达、长度截断或作用域不明确，仍可待核；不凭本轮修复声称全部推荐准确率提高。完整源复核沿用当前事件和专业记录提取规则，而不认证外部资质真实性。首次失败、阶段性实现失误与最终记录另存在私有 `yanxu-guided-completion.PxYfc6k1`，旧报告原样保留。
