# 教学方法否定比较：恢复证据，不等于完成推荐

2026-09-09，内部研发记录。没有训练、启封新题、替换模型或发布。

## 已确认的原因

已暴露开发案例PD42的本人现场、本人远程两份资料，都包含“而不是只评价‘挺好’”的教学方法说明。实际Java逐个判定检查显示：本人、完成动作、上下文与角色检查通过；`NEGATIVE`唯一命中是其中的“不是”。因此模型前的整段过滤把两份资料都标为`no_evidence`。同事授课反例没有本人完成动作，单独保留。

原PD42完整需求另外还有引号内方法被拆分、被动句课程—对象绑定及未核条件问题。本次不把恢复模型输入等同于解决这些问题。

## 本次改动

- Java `ProfessionalEvidence`和Python worker增加一致的、范围受限的方法反馈比较识别：同一段内前面须有明确本人完成授课表述；当前句须是方法／步骤／流程描述，包含具体说明或反馈动作；句尾须是完整引号包围的反馈比较。
- 整个比较分句不参与正向检索或能力引文，原文及段落范围完整保留。不能把“并非本人授课”、同事经历、助教角色、未来安排、引用履历或不完整引号转为肯定证据。
- 不从比较分句推导授课人、经历、资格或授课形式。段落间不借用前面独立记录；后面才出现的本人经历也不能反向充当恢复条件。
- 未扩充课程领域词典、未修改真实简历或历史相关性标签、未用高模型分覆盖硬性条件。

## 实际结果

### 原BGE INT8与真实历史材料

按冻结的原模型与实际响应复现基线，随后执行9次当前BGE请求：PD42三份开发资料，以及19份真实简历对应8条历史模拟需求。

- PD42的现场、远程本人资料由`no_evidence`变为`ready`，各恢复2个连续原文单元；同事反例没有恢复。
- 原PD42完整需求仍全部未准入、没有推荐，未通过完整业务验收。
- 19份×8条需求的152份候选审计逐字段完全一致，原准入和入选名单不变。不能宣称真实简历准确率提高。

### 额外现场／远程业务对照仍失败

在诊断后另外编写客户服务、古籍页码核对、园艺工具清洁三个主题的对照，每题包括本人现场、本人远程但学员现场、同事授课三人。保留相同需求与资料，修改前／后各实际执行3次BGE请求。这些是已知规则的合成回归，不是新盲测。

修改后本人候选的主题与历史经历已经`source_supported`，但“面对面授课形式”仍为`needs_evidence`；三条需求修改前后都没有推荐。事件解析器仍把显式授课形式、方法步骤与比较句列为未解析上下文，并存在另一层段落否定检查。记录失败，不删去现场条件或换成容易通过的题。

下一步必须检查并修复课程、本人授课动作与形式的原文绑定，保留同事／助教／远程学员活动等反例和完整上下文。本次恢复证据是前置修复，不是推荐链路已可上线的证明。
