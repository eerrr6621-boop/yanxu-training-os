# 未来对象与历史对象：测试契约迁移

2026-09-08，开发回归记录。不是模型训练结果，也不是已上线说明。

## 为什么部分旧断言要变更

旧测试把“培训对象：X”与“必须有这门课的授课记录”并列，隐含解释为必须过去给 X 讲过同课。这比客户原始要求更强。现在普通未来对象作为适配背景保留；只有明确要求适配、或明确把过去授课与该对象绑定时，才核对相应的硬条件。不能仅为保持旧断言绿色而保留额外门槛。

本轮原始八组测试、迁移前业务字段注释代码及旧失败另行封存，未删除。已暴露的模型评测集与历史标签没有随此修改。

## 具体迁移

- RequirementInputTest：普通未来对象不匹配不单独拒绝主题候选；新增独立上下文数组、字段原文及规范化坐标核对。其他课程的对象仍不得算作该课程的对象证据。
- RequirementContractTest：普通未来对象和纯描述括注转上下文。数量比较、排除、括号不完整等旧硬待核仍保留。
- RequirementTopicIntegrationTest：一般同课程历史不自动绑定未来对象；原显式对象回指、本人、完成状态、多课程历史隔离测试保留。
- RequirementNarrativeTest：明确历史受众的断言检查实际课程历史绑定，而不再要求它出现在通用 features 容器；普通岗前培训对象转上下文。
- FocusedQuerySchemaTest：保留检索全文与坐标测试；普通未来对象不额外拒绝，同时确认不会向上下文借入其他课程的对象证据。
- NearbySelectionTest：补充主题入口与未来对象的旧拒绝改为主题候选加适配待确认；明确历史要求、交通与同分规则不变。
- AudienceContractTest、TeachingEventBindingTest：用于检测错对象、跨事件借对象的辅助需求改为明确“以前给这类学员讲完这门课”，保留这些反例的拒绝要求；普通未来背景另测为非硬条件。
- test_teaching_event_protocol.cjs：原两条“未来对象 + 普通历史”输入保留，改为允许不同既往对象；另增两条明确同对象历史输入，继续验证错误对象待核、他人授课不放行。共 98 项协议检查，不运行模型。
- test_requirement_input_http.cjs：实际引导表单与纯文本普通对象按非硬上下文核对；追加明确适配的纯文本正反例、字段来源检查。引导式自由补充要求仍保持现有待核门槛，不借此次迁移绕过。55 项隔离 HTTP 检查通过。

## 字段来源的补充

RequirementInput.annotate 为 audience_context 单独附加填写字段来源，不把它混入 requirement_coverage。只有原范围在规范文本中仍指向完全相同的字符，才标注为规范字段坐标；否则保留原 matching-text 审计，不编造原始字段位置。不改变候选的准入结论。

首轮局部编译及九组测试已通过。《命名课程》作主语的强条件漏识别已另行修复并通过 19 项边界检查；最终以全量检查和重新冻结后的实际回放为准。断言通过不代表推荐准确率提高。

## 保留的限制

复核还发现“必须有实际授课记录，并且必须以前给这类学员讲完这门课”这一重复复合句会保守进入待核，尽管测试原文有相符记录。输入与完整输出另存 `compound-history-pending.json`，没有把它改标成真实不合格；后续应修复组合解析。引导字段 preference / extra 目前仍整段待核，不能宣称所有自然语言硬条件已完整识别。
