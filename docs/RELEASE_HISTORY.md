# 公开更新记录维护约定

## 每天一份，对同日内容持续整合

`web/releases.js` 是公开更新页的数据源。每个有记录的北京时间日期只保留
一份条目；同一天继续迭代时修改已有条目，不新建 R1、R2 等独立公开卡片。
工程级过程继续记入 `CHANGELOG.md` 和 Git；不因此安排定时发布或自动上线。
2026-09-06 整理前的 21 条公开记录保存在
`docs/release-history-before-daily.json`，仅供审计，不再重复展示。

内容按当天最终有效行为整合。撤销的实验不当作当前功能；重复的视觉微调合并。
公开数据只包含正式上线内容；尚未上线的草稿保留在维护记录中，不进入网页。
内部 `status` 字段用于校验，页面不展示“已发布／本地预览”等状态或筛选。
每个日汇总只展示日期、版本、具体改进和可核实的更新时间。
上线记录只在真实部署验收后加入；本地运行、提交或推送 GitHub 均不等于上线。

## 时间含义

- `date`：北京时间的日历日，按日期从近到远；早期仅知月份则保留 `YYYY-MM`。
- `sections[].recordedAt`：真实维护记录时间，格式 `YYYY-MM-DDTHH:mm:ss+08:00`。
  修改当天说明时记入当次实际整理时间，来源 `timeSource: recorded`。
- 历史记录能核实到 Git 时间时采用提交者时间（`%cI`），不混用作者时间，
  并在 `source` 保存提交号；没有精确时间则使用 `null`，不得补成 `00:00:00`。
- 页面底部显示该天最近的有效记录时间（北京时间）。它不是
  浏览页面的时间，也不是推断的生产部署时间；折叠详情后仍保留可见。
- 部署验收成功后采用实际服务器记录时间并注明 `timeSource: deployment`；
  历史提交时间的含义保持不变，不补造早期上线时分秒。

## 验收

运行 `node scripts/test_release_days.cjs`；它覆盖日期唯一性、未上线草稿隔离、
时间有效性、24 小时制、北京时间、缺失精度与原始归档完整性。
修改数据结构时同时更新 `updates.js` 和两者在 `updates.html` 中的缓存键，
并检查桌面/移动端展开与折叠显示。共享样式的缓存键须在四个页面同步更新。
